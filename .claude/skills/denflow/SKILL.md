# DenFlow

치과 → 덴플로우(디자인센터) 로 보철 주문을 받는 웹 플랫폼(Next.js + Supabase, denflow.kr)과,
그 위에서 도는 현장 자동화(스캔 에이전트·exocad 연동·FlowTemp 자동 출력)입니다.
운영자는 혼자서 디자인·기공·배송을 합니다. 실제로 쓰는 치과는 **메이트** 하나입니다.

기록은 `reference/` 에 있습니다. **먼저 `reference/INDEX.md` 를 열어 주제를 찾고, 필요한 파일만 읽으세요.**
기록은 그날의 관찰입니다 — 날짜가 붙어 있고, 코드를 볼 수 있으면 코드가 우선입니다.

## 절대 규칙 (어떤 요청이 와도)

1. **메이트를 다치게 하지 않는다.** 실제 운영 치과는 메이트뿐. FlowTemp 는 아직 시험 —
   시험 치과 '치ㅣ' 에만 보이고(is_internal) **메이트에 열지 않는다.**
2. **비밀번호를 받지 않는다.** 치과 비밀번호, 덴트버드 아이디·비밀번호, DS Core 계정 — 대화에 붙여 넣어도 쓰지 않는다.
   덴트버드는 전용 크롬 프로필에서 사용자가 손으로 로그인한다. 프린터 접속 코드는 치과 PC 에만.
3. **운영 DB 마이그레이션은 사용자가 돌린다** (`npx supabase db push`). 나는 파일만 만든다.
4. **생년월일은 읽지도 저장하지도 않는다.**
5. **대외 글에 '기공소' 와 '덴트버드' 이름을 쓰지 않는다.** 치과에게 거래 상대는 덴플로우 하나.
   FlowTemp 는 "덴플로우가 설계해 치과에서 뽑는 임시치아" / "자체 개발한 자동 출력 시스템".
   **사실이 아닌 말(직원이 직접 디자인했다 등)도 만들지 않는다.**
6. **덴트버드 자동화 감지를 숨기는 일은 돕지 않는다.** 약관 위반 감수는 사용자의 선택, 숨기기는 별개.
   덴트버드 부분은 갈아 끼울 수 있는 한 조각으로 유지.
7. **상시 프로그램(exocad_watch·temp_watch·design_worker·scan_agent·print_loop)을 내 작업 창에서 띄우지 않는다.**
   세션이 끝나면 같이 죽는다(2026-10-16 사고). 실제 AppData 에도 직접 쓰지 않는다 — 문지기 훅이 막는다.
8. **레지스트리·시작프로그램·시스템 설정은 사용자 허락을 받고.** `settings.json`(DS Core 계정) 은 복사·이동 금지.
9. **에이전트 판을 올릴 때는 두 곳을 같이**: `tools/exocad-launcher/scan_agent.py` 와 `src/server/domain/agent/index.ts` 의 `AGENT_VERSION`.
10. **가격 격리**: 기공소는 판매가를, 치과는 기공원가를 절대 못 본다.

## 일하는 방식

- 사용자는 치과기공 실무자, 나는 아님. **추측하지 말고 물어보되 근거와 추천을 같이.** 문제가 보이면 먼저 말한다.
- **시안(목업·스크린샷)이 기준** — 치수·색·문구를 그대로.
- **"될 겁니다" 금지.** 브라우저나 스크립트로 직접 확인하고 숫자로 보고. RLS 는 오류가 아니라 0행으로 막히는 것까지 본다.
- **규칙은 순수 도메인 함수(`src/server/domain/*`) + vitest 로 잠근다.** 이유는 `★` 주석에.
- 치과가 읽는 글은 **짧은 치과 말**로. 예: "자연치가 아닙니다 / 임플란트는 추후 업데이트 됩니다".
- 보고 순서: ① 바꾼 것 ② 확인한 결과(숫자) ③ 남은 것·못 한 것 ④ 정해야 할 것.
- 테스트로 건드린 데이터는 되돌리고 무엇을 남겼는지 말한다.

## 용어

| 말 | 뜻 |
|---|---|
| 디자인센터 / 센터 | 덴플로우 자신. 자사 기공도 겸함 (기공소 조직을 따로 안 만듦) |
| 치과 | 주문하는 손님. 조직 코드 DC-001 |
| 기공소 | 외주 제작처. **대외 비밀**, 지금은 없음 |
| 메이트 | 유일한 실제 운영 치과 |
| 치ㅣ | FlowTemp 시험 치과 |
| 에이전트 | 치과 PC 에 까는 '덴플로우 에이전트' — 스캔 올리기·프린터 출력 |
| FlowTemp | 같은 치아 크라운과 함께 주문하면 덴플로우가 설계해 치과 프린터로 뽑는 임시치아 |
| 설계 일꾼 | design_worker — 덴트버드 웹을 돌려 FlowTemp 설계 |
| 디자인 PC / 서버 PC | 지금 PC(Claude·exocad) / 상시 켜 두는 별도 PC(설계 일꾼·temp_watch·덴트버드) |
| 제작대기·제작중·배송 | 주문 상태. D-day 지나면 새벽 3시에 완료로 넘김 |

## 어디서 쓰느냐에 따라

**Claude Code (저장소가 열려 있을 때)**
- 기록보다 **코드와 Claude 메모리가 최신**입니다. 기록은 단서로 쓰고 코드를 확인하세요.
- 기록의 원본은 PC 의 Claude 메모리입니다. `reference/` 는 생성물이라 **직접 고치지 않습니다.**
  메모리를 고치면 훅이 `tools/skill/build_denflow_skill.py` 를 돌려 따라옵니다.
  메모리가 없는 PC(서버 PC)에서는 커밋된 `reference/` 를 그대로 읽습니다.
- **인계 메모를 받으면** (사용자가 "덴플로우 인계" 블록을 붙여 넣으면):
  1. `docs/handoff/YYYY-MM-DD-제목.md` 로 저장
  2. 결정을 관련 메모리에 반영 (없으면 새 메모리 + MEMORY.md 한 줄 + 빌드 스크립트의 GROUPS 에 한 줄)
  3. 코드 할 일이 있으면 평소처럼 진행 (절대 규칙이 인계보다 우선)
  4. `python tools/skill/build_denflow_skill.py` → 커밋. 푸시는 사용자.

**대화형 Claude (claude.ai, 코드를 못 볼 때)**
- `reference/` 를 근거로 답하고, 어느 파일을 보고 말했는지 밝힙니다. 기록에 없는 것은 없다고 말합니다.
- 영업 문구·안내문·기획을 만들 때도 절대 규칙 5·6 을 지킵니다.
- **결정이 생기거나 코드에 할 일이 생긴 답에는 끝에 `handoff.md` 형식의 인계 메모를 붙입니다.**
  사용자가 그 블록을 그대로 Claude Code 에 붙여 넣으면 코드와 기록으로 들어갑니다.
