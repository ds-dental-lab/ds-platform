**2026-08-14 시작.** 사용자 요구를 그대로 옮기면:

> 접수 → 디자인센터 / 제작대기 → 기공소 / 재스캔 → 치과.
> 관리자 **+ 사용자 복수**가 받고, 각자 번호를 넣고 고치고 On/Off 하며,
> 그 화면은 **계정정보**에.

## ★ 대표번호와 다른 칸입니다

```
organizations.tel     청구서에 찍히는 대표번호   (그대로 둡니다)
user_profiles.phone   알림톡 받을 번호 — 사람마다
user_profiles.alimtalk_on   켜짐/꺼짐
```

★ **칸을 새로 안 만들었습니다.** `user_profiles.phone` 이 처음부터 있었는데
  코드 어디서도 안 쓰고 있었습니다(전체 훑어 확인). 뜻이 같은 칸이 둘이면
  언젠가 서로 다른 값이 들어갑니다.

★ **정책도 새로 안 만들었습니다.** `profile_update` 가 이미
  `id = auth.uid()` 라 "사용자도 스스로 고칠 수 있어야 한다" 가 충족됩니다.

★ 기본은 **켜짐**. 번호를 넣는 행위가 곧 "받겠다" 입니다. 번호가 없으면
  켜져 있어도 안 나갑니다.

★ **비우는 것 ≠ 끄는 것.** 끄는 것은 번호를 둔 채 잠시 멈추는 것(휴가·야간)
  입니다. 번호를 지웠다 다시 넣게 하면 그때마다 오타가 납니다.

## 번호 다루기 (`domain/alimtalk`, 테스트 18개)

저장은 **숫자만**, 화면은 **하이픈**. 섞이면 같은 사람이 두 번 받거나
대행사가 거부합니다. `+82` 는 `0` 으로 되돌립니다.

★ **휴대전화만** 받습니다. 유선번호는 저장은 되고 **발송만 조용히
  실패**합니다 — 그 실패가 아무 화면에도 안 보이므로 여기서 막습니다.

## 언제 누가 받나

`eventFor(from, to)` 가 정합니다. **바뀐 순간에만** 봅니다 — 같은 상태로
다시 저장하는 일이 있어서, 'now 가 무엇인가' 로 보면 한 건에 여러 번
나갑니다. **접수로 되돌아온 것도 새 주문이 아닙니다.**

## 대기열 (`alimtalk_queue`)

아직 안 보내므로 **누구에게 어떤 문구로 갈 뻔했는가**를 줄로 쌓습니다.
발송이 붙으면 이 표를 읽어 내보내면 되고 **쌓는 코드는 안 바뀝니다.**

★ **사람마다 한 줄.** 조직 하나로 묶으면 '둘은 갔고 하나는 실패' 를
  표현할 수 없습니다.
★ **받는 사람과 번호를 그때 박아 둡니다.** 나중에 번호를 바꿔도 이 줄은
  '그때 누구에게 갔다' 를 말해야 합니다(청구서 받는 곳과 같은 이유).
★ **넣는 것은 service_role 뿐.** insert 정책을 안 만듭니다 — 사용자 열쇠로
  남의 폰에 알림톡을 꽂는 길을 안 엽니다.
★ 계정정보에 **'나에게 갈 뻔한 것'** 목록이 붙습니다. 나가기 전에 문구를
  눈으로 검증할 유일한 방법입니다.

## ★ 막혀 있는 것 — 사업자등록

알림톡은 **사업자등록 → 카카오톡 채널 → 템플릿 사전심사** 가 있어야
나갑니다. 즉석에서 아무 문구나 못 보냅니다.

준비할 순서:
1. 카카오톡 비즈니스 채널 개설 (사업자등록증 필요)
2. 발송 대행사 (솔라피·알리고·NHN 등). 카카오와 직접 계약보다 쉽습니다
3. **템플릿 사전심사** — 며칠 걸립니다. 채널이 생기는 즉시

초안 셋 (변수 `#{}`):

```
[새 주문 접수] #{치과명} 에서 새 주문이 들어왔습니다.
              환자: #{환자정보} / 요청시한: #{요청시한}
[제작 의뢰]   #{치과명} 건이 제작대기로 넘어왔습니다.
              환자: #{환자정보} / 요청시한: #{요청시한}
[재스캔 요청] #{주문번호} 건에 재스캔이 필요합니다. 사유: #{사유}
```

★ 광고성 문구가 섞이면 **반려**됩니다. 정보성만.

승인 뒤 **템플릿 코드**를 받으면 발송 함수 하나만 꽂으면 됩니다 —
나머지는 이미 서 있습니다. 반나절.

## ★ 확인 못 한 것

**줄이 실제로 쌓이는지 못 봤습니다.** 화면에서 '재스캔 요청' 을 눌러
확인하려 했는데 브라우저 도구가 계속 이상했습니다
([[ds-flow-working-style]] 에 적어 뒀습니다). **사람이 한 번 눌러
봐야 합니다** — 치과 계정정보에 줄이 뜨면 성공입니다.
