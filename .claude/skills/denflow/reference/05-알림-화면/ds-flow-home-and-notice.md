**2026-08-12.** 사용자가 개인정보 쪽을 미루고 *"홈페이지 구성 완성도"* 로 옮겼습니다.

## ★ HOME 금액은 섹터마다 **다른 것을 셉니다**

| | 세는 날짜 | 구간 |
|---|---|---|
| 치과 | **접수일** | 자기 정산기간 |
| 디자인센터 | 배송일 | **달력 월** |
| 기공소 | 배송일 | 자기 정산기간 |

*"치과는 접수기준, 디자인센터는 배송일 기준으로"*.
치과가 알고 싶은 건 청구서가 아니라 **"이번 달에 얼마나 쓰고 있나"** 입니다.
스무 건 넣고 두 건 나갔으면, 배송으로 센 숫자는 씀씀이를 안 보여 줍니다.

**그래서 치과 HOME 과 치과 정산은 일부러 다른 숫자입니다.** 하나는 넣은 것,
하나는 나간 것 — 카드 물음표에 그렇게 적어 뒀습니다. 안 적으면 전화가 옵니다.

**디자인센터만 달력 월인 이유** — 거래처 치과들의 기준일이 제각각이라
'이번 정산기간' 이라는 게 하나로 안 나옵니다. 없는 기준을 지어내느니
달력 월이라고 밝히는 편이 낫습니다.

규칙은 `domain/billing` 의 `moneyRange` / `moneyRanges`.
셈은 정산과 **같은 함수**를 씁니다 (`resolvePartyPrice`·`itemAmount`) —
갈라지면 두 화면이 서로 다른 말을 합니다. 조정(billing_adjustments)은 안 더합니다.

## 추이 그래프 — 가로로 눕혔습니다

세로 막대로 만들었다가 되돌렸습니다. 창 1024 에서 카드가 225px 이 되고
여섯 칸에 24px 씩 남는데, 금액 글자(`1,438만`)가 38px 이라 **옆 막대 글자와
실제로 겹쳤습니다**. 이 카드는 좁고 깁니다 — 가로로 누우면 달·막대·금액이
각자 칸을 갖습니다. 좁은 카드에 세로 막대를 다시 세우지 마세요.

## ★ 추이는 이제 **치과에만** 있습니다 (2026-08-15)

*"디자인관리자 home 에서 사용금액추이 영역은 필요없어보여, 작업리스트
칸을 늘려서 다시 맞춰줘"*. 디자인센터·기공소는 이 화면을 **일하려고**
엽니다 — 무엇을 잡아야 하는지가 먼저이고, 매출 흐름은 정산·통계에서
제대로 봅니다. 치과 관리자에게는 남깁니다(작업 리스트가 없어서 빼면
왼쪽이 금액 카드 하나로 휑해집니다).

### ★★ 자리 배치는 `homeLeftLayout` (domain/worklist) 이 정합니다

세 칸이 **같은 줄에서 끝나야** 화면이 안 어긋나는데, 그 조건이
`flex-1` 을 누가 갖느냐 하나에 걸려 있습니다. 화면 코드 안에서 따지면
카드를 넣고 뺄 때마다 조용히 깨집니다 — **실제로 그래서 옮겼습니다.**

```
추이가 있으면   → 추이가 남는 높이를 가져감
목록이 있으면   → 그 목록
둘 다 없으면    → 진행중 상태·이슈
```

시험 하나가 이 규칙의 전부입니다 — 여섯 경우(세 섹터 × 금액 보임 여부)
모두 **늘어나는 칸이 정확히 하나**.

### ★★ '칸끼리 맞는가' 와 '화면을 채우는가' 는 다른 질문입니다

추이를 빼자 **셋이 사이좋게 짧아져** 화면 아래가 남았습니다. 그런데 제
확인은 '세 칸이 같은 줄에서 끝나는가' 만 봐서 **통과해 버렸습니다.**
사용자가 "home화면 아래 비어잇는거 확인햇어" 로 잡아 줬습니다.
→ `lg:min-h-[calc(100vh-76px)]` (76 = 상단바 48 + 여백 14+14).
**앞으로는 둘 다 잽니다.**

## 작업 리스트 (디자인센터)

**재스캔·접수·디자인 셋만.** 제작대기부터는 기공소 일이라 빼야 합니다 —
넘긴 뒤에도 남으면 "할 일 열두 건" 으로 보여 정작 급한 두 건이 묻힙니다.
차례는 **요청시한 이른 것부터** (접수순 아님).
디자이너 칸은 담을 칸도 고를 사람도 없어 아직 '미지정' 입니다.

## 공지사항 — 디자인센터만 씁니다

*"공지사항은 디자인센터가 글 쓸권한을 줘"*. 사이드바 '게시판' 이 여기로 갑니다.

- **받는 쪽을 고릅니다** (전체·치과·기공소). 모두에게 보내는 버릇이 들면
  아무도 안 읽습니다
- **임시저장** (`published_at is null`). 쓰다 만 글이 치과 화면에 떠 있으면
  그게 사고입니다
- **고쳐도 차례가 안 바뀝니다** — `published_at` 을 now() 로 덮으면 오타 고친
  지난달 공지가 맨 위로 올라옵니다
- **지우기는 `deleted_at`.** delete 정책을 안 만들었습니다 —
  "그런 안내 받은 적 없다" 가 나올 때 근거입니다
- 상세 화면 없음 — 목록에서 펼쳐 읽습니다

확인 (실제 계정 JWT · 대조군 포함): 치과 2 · 기공소 2 · 디자인센터 4(임시 포함),
치과 쓰기 42501 차단, 기공소 고치기·지우기 0줄, 디자인센터 4줄.

관련: [[ds-flow-billing-model]] [[ds-flow-price-isolation]] [[ds-flow-backlog]]

## ★ 검수 목록 모달 — 만들었다 **되돌림** (2026-08-19)

'오늘 배송 예정' 카드에 '검수 목록 N건' 단추 + 모달(상태·환자·주문번호·
보철 요약)을 만들어 배포까지 했는데, 사용자가 **"없던 일로 해줘"**.
커밋 e67290b 로 넣고 1b0be3f 로 되돌렸습니다 — 다시 만들자는 말이
나오면 그 커밋에 완성본이 있습니다 (TodayDeliveryDialog +
fillDeliveryDetails, 플레이그라운드 검증까지 끝난 상태).

★ 같이 넣었던 **배송 전환 알림 제거는 유지**입니다 ([[ds-flow-chat-and-alerts]]).
  카드의 짧은 목록은 원래부터 있었고 그대로입니다.

## 주문목록 단추 둘 (사용자 2026-10-22)
- **취소**: 기본 목록에서 빠짐(아무 상태도 안 고르면 취소 제외). 상태 단추 맨 끝에 「취소」가 있어 누르면 그것만. LIST_STATUSES 아홉.
- **임시치아**: 이슈 단추 줄 끝에 「임시치아」(치과·센터, 기공소 없음). 센터는 기본에서 빠진 temp 주문을 여기로만, 치과는 골라 보기. 이름은 'FlowTemp' 대신 **'임시치아'** — 목록·꼬리표는 '무엇인가'를 쓰고, FlowTemp 는 책갈피·제품 이름(상표)으로만.
