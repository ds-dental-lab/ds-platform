# 바이트 재정렬 자동화 (exocad 전문가모드 → 교합정렬)

2026-10-28 사용자 요청. "수동으로 하는데 너무 귀찮다, 될지 말지 고민해 봐라."

## 사용자가 말한 사실
- 스캔은 **항상 맞물려서** 온다(스캐너가 정렬해 보냄). 그런데 exocad 에서 바이트 스캔으로 **재정렬하면 조금씩 움직인다**.
- 기공에서는 그 작은 값이 결과를 가른다.
- **free-end 케이스는 거의 무조건** 재정렬해야 한다.
- 재정렬하면 **대부분 좋아지지만 가끔 나빠진다**.
- 원하는 것: "대부분 좋아지는 쪽" 을 **기본값**으로. 사람이 안 눌러도 재정렬된 상태로 열리게.
- 떠올린 아이디어: 바이트 스캔 **영역을 조절하면서 붙여 보고** 결과가 어떻게 바뀌는지 보는 프로그램.

## 지금 코드 상태
- 런처(tools/exocad-launcher/launcher.py)는 exocad 화면을 안 누름. 케이스 폴더·프로젝트 파일만 만듦.
- 바이트 스캔은 exocad 가 자동으로 집는 이름을 몰라 **원래 이름 그대로** 둠(`BITE` 정규식, place_name).
- exocad GUI 자동화는 없음(덴트버드만 셀레니움). 교합정렬을 클릭으로 흉내 내는 건 새 공사이고 깨지기 쉬움 — 마지막 수단.

## 결정
- 2026-10-28 사용자: **"나중에 해보자"**. 시작 조건: 정렬 끝내고 저장한 케이스 폴더 1개 + 케이스 10개. 서버 PC 돌아온 뒤.

## 내 의견(2026-10-28)
1. 계산 자체는 된다 — 하악(또는 상악)을 바이트 스캔에 ICP 로 다시 맞추는 것은 메쉬 합치기 때 쓴 도구(trimesh)로 가능. 런처가 파일을 쓰기 전에 적용하면 exocad 는 정렬된 채로 연다.
2. 어려운 건 "좋아졌다/나빠졌다" 판정. exocad 알고리즘과 우리 ICP 가 같은 답을 내는지 모름. **먼저 10케이스로 재어 봐야 함**: 스캐너 정렬 vs exocad 재정렬 vs 우리 ICP — 이동·회전 크기와 바이트 스캔 잔차(RMS).
3. 영역 조절 뷰어는 2단계. 잔차·접촉 분포를 보여 주면 "나빠지는 경우" 를 거르는 기준을 찾을 수 있음.
4. 스캐너 정확도가 수십 µm 라 그 아래 차이는 소음 — 기준을 µm 단위로 정해야 함.

**Why:** 사용자가 매 케이스 손으로 하는 단계를 없애고 싶어 함. 품질이 걸린 일이라 "자동으로 바꿨는데 나빠짐" 이 가장 큰 위험.
**How to apply:** 이 주제가 다시 나오면 GUI 클릭 자동화부터 제안하지 말 것. 먼저 사장님이 정렬 끝내고 저장한 케이스 폴더(파일 이름·프로젝트 파일)와 케이스 10개 측정부터. 관련: [[ds-flow-exocad]], [[ds-flow-fdm-print]]
