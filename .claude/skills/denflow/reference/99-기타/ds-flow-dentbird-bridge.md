# 덴트버드 브릿지 화면 (실측 2026-10-28, 크롬 확장으로 읽음)

다서울 약속(2026-11-02~08 브릿지)을 위해 본 것. 케이스: 사용자가 준 시로나 dxd(26·27 프렙)를
`Desktop\일\dxd-conversion.exe`(DS Core 로그인 필요, 사용자가 직접) 로 풀어 상·하악 stl 을 올림.

## 사실
- 덴트버드 '신규 → 유형' 은 **Crown · Modeler · Studio · Batch** 넷. **Bridge 유형은 없다.** 브릿지는 Crown 안에서 만든다.
- 앱 목록(왼쪽 위 격자): Cloud · Crown · Milling · Modeler.
- 올리기는 싱글과 같다 (`import-file-input` → `import-next-btn`). AI 분석이 끝나면 `/crown/preparation`.
  - 잇몸 마스크(GingivaMaskUpper.stl) 같은 추가 파일은 '추가(수술 전 등)' 칸에 들어가며 `import-mesh-delete-<id>` 로 지울 수 있음. 매크로는 악 두 개만 올리므로 신경 안 써도 됨.
- 3D 화면의 보철 라벨 `restoration-label-layer` 안에 **이웃한 보철 둘 사이** `bridge-link-toggle-btn` 이 있다.
  - svg class `crown-icon-bridge-unlink`(안 이어짐) / `crown-icon-bridge-link`(이어짐).
  - 누르면 `bridge-link-panel` 이 뜨고 **`bridge-link-panel-apply-btn`(적용) 까지 눌러야** 반영됨.
  - 반영되면 사이드바 `workspace-preparation-tooth-info-setter` 글이 "크라운 26 / 크라운 27" → **"브릿지 26-27"** 로 바뀜. 프리셋 셀렉트도 하나로 합쳐짐.
- 치아 라벨(`component-floating-label-button`, 글이 치식)을 누르면 `tooth-planning-panel`:
  - 유형 단추: `tooth-planning-type-natural-full-crown` · `partial-crown` · `implant-full-crown` · **`pontic`** · `natural` · `missing`
  - `tooth-planning-apply-btn`(적용, 바꾸기 전엔 disabled) · `tooth-planning-close-btn` · `detected-tooth-delete-btn`
  - 자연치 라벨(회색, `detected-tooth-label-overlay`)도 눌리므로 **폰틱 = 그 자리 라벨 → pontic → 적용**.
  - ★ 미확인: AI 가 '결손치' 로 잡은 **빈 자리에 라벨이 뜨는가**. 이 케이스엔 결손치가 없어 못 봄. 진짜 폰틱 케이스에서 확인할 것.
- 사이드바 치식 그림(`workspace-preparation-tooth-info-display`)은 **보기 전용** — 눌러도 아무 일 없음.
- 준비 화면 도구막대에 **`preparation-toolbar-tool-occlusion-alignment`** 가 있다 — [[ds-flow-bite-realign]] 과 관련, 나중에 볼 것.
- 이날 로그인 계정은 **Free(티미 스, 2023 샘플)** — 리허설의 유료 Starter 계정과 다름. 분석·브릿지 연결까지는 건수 안 듦. 내보내기는 유료 계정으로.

## 매크로에 붙일 순서(초안)
1. 싱글과 같이 올리고 분석 → `detected_teeth` 로 치식 대조(지대치만 잡힘).
2. 폰틱마다: 라벨 클릭 → `tooth-planning-type-pontic` → `tooth-planning-apply-btn`.
3. 묶음의 이웃 쌍마다 `bridge-link-toggle-btn`(어느 단추가 어느 쌍인지는 라벨 좌표로 정함) → `bridge-link-panel-apply-btn`.
4. setter 글이 "브릿지 a-b" 인지 확인 후 `workspace-preparation-design-btn` → 생성 → 내보내기.
5. ★ 미확인: 생성 시간, 내보낸 파일 이름(싱글은 `…_16-16-crown.stl`; `dentbird_case.teeth_from_name` 이 브릿지를 거절함 — 이름 규칙을 보고 풀 것), 차감 건수.

## 생성 뒤 (실측 2026-10-28, 같은 케이스)
- `workspace-preparation-design-btn` → `/crown/crown?caseUniqueID=…` → `generate-crown-btn`. 크라운 둘 생성 **약 1분**.
- 끝나면 상태: "브릿지 26-27 · 브릿지 준비됨 · **미조립** / 크라운 26 생성됨 / 크라운 27 생성됨" + 안내 "툴바의 어셈블 버튼을 클릭하여 브릿지를 완성하세요". `design-status-flag-NotAssembled`.
- **조립 전(미조립)**: 라벨 26 을 누르면 크라운 툴바가 뜨고 **싱글과 같은 패널**이 다 있다 — `toolbar-tool-inner`(inner-input-minimalThickness 등 7칸 + inner-apply-btn), `toolbar-tool-refine`(refine-group-Adapt: occlusal/proximal/gingival 입력과 cut/preserve 단추, Outer 탭 '최소 두께 부족' 경고). **→ 매크로의 apply_all(내면·교합인접·최소두께)은 조립 전에 크라운마다 돌리면 된다.**
- 툴바에 `toolbar-tool-connect`(브릿지 커넥터): `connect-select-connector`, 단면 형태 `connect-cross-sectional-shape`(4가지), 크기 `connect-size-slider-횡단`·`connect-size-slider-수직`(기본 5.0mm·5.0mm), `connect-size-info`("최적 12.5mm²"), `connect-sub-renderer-switch`(치아 초점 보기). 연결부 강도는 여기서.
- `toolbar-assemble-btn`(합치기) → 10초쯤 → "브릿지 조립됨". 조립 후에는 라벨이 "26-27" 하나가 되고 툴바에 refine(이동·변형/외형만, Adapt 탭 없음)과 `toolbar-detach-btn`(분리)만 산다. 내면·교합 조정은 잠김.
- 분리(`toolbar-detach-btn`)는 확인 대화("조립 후 수정한 내용이 삭제됩니다 · 개별 크라운 형태는 유지") → 확인 단추(글 '확인').
- `views-thickness-inspection-btn`(두께 검사 보기) 로 얇은 곳을 색으로 볼 수 있음(aria-pressed).
- ★ 미확인: 내보내기 파일 이름·차감 건수·메쉬 구멍 여부(STL 받아서 trimesh 로 봐야 함). Free 계정이라 사용자에게 물은 뒤.

## 오류 날 자리 (2026-10-28 사용자 "오류가 날법한곳 알아서 찾아서 학습해봐" — 같은 케이스로 실측)
1. **생성 단추가 안 먹음** — `/crown/crown` 으로 넘어온 직후 `generate-crown-btn` 을 눌러도 아무 일 없음(실제로 한 번 겪음). 싱글 매크로의 "먹을 때까지 몇 번" 되풀이가 브릿지에도 그대로 필요. 글에 '준비 중/생성 중/생성됨' 이 뜨면 시작된 것.
2. **Smart order 로 돌아가면 브릿지 연결이 풀림** — 돌아가면 "크라운 26 / 크라운 27" 로 돌아오고 토글이 unlink. 되돌아갈 일이 생기면 폰틱·연결을 **다시** 해야 함.
3. **합치기(assemble) 단추는 크라운을 고른 뒤에만** 툴바에 뜸. 아무것도 안 고르면 툴바 자체가 없음.
4. **브릿지 링크 토글은 '적용' 까지** — 토글만 누르면 패널이 뜨고 setter 는 안 바뀜. `bridge-link-panel-apply-btn` 필수. 3유닛은 토글 둘을 각각 적용(처음엔 "폰틱 25 · 브릿지 26-27", 둘째 적용 뒤 "브릿지 25-27").
5. **폰틱을 찍으면 "폰틱 기준점 설정" 패널**(`pontic-guide-panel`, `pontic-guide-close-btn`)이 뜸 — "빨간색 포인트를 결손 부위로 이동하여 폰틱 위치를 지정합니다". 3D 캔버스 드래그라 testid 로는 못 함. ★ 진짜 결손 케이스에서 **기본 위치가 쓸 만한지** 보고 결정. 이 케이스(자연치 25 를 폰틱으로)는 안 옮기고도 생성됨.
6. **조립 후엔 내면·교합 조정 잠김** — 값 넣기는 조립 전에. 분리(`toolbar-detach-btn`)하면 확인 대화("조립 후 수정 삭제") 가 뜨고 조립 후 손본 것이 날아감.
7. **내보내기 창이 늦게 뜸** — 브릿지는 "내보내기 처리 중..." 이 20초 넘게 감(싱글 매크로의 5×4초 기다림으론 모자랄 수 있음). `export-dialog-title` 이 iframe 안에 뜰 때까지 기다릴 것.
8. **내보내기 항목이 다름** — 싱글은 `export-item-CROWN-TOOTH-26` 들, 브릿지는 **`export-group-BRIDGE`** 하나("브릿지 25-27"). 지금 EXPORT_JS 는 '크라운 NN' 글을 긁어 crowns 를 만들므로 브릿지에선 빈 목록 → 대조 코드를 고쳐야 함. iframe 에 `count`·`deduction` testid 가 있어 글 정규식 대신 쓸 수 있음.
9. **차감 건수 = 유닛 수** — 싱글 둘 2건, 브릿지 25-27(폰틱 포함) **3건**. 폰틱도 1건. 요금 계산·건수 경고에 반영.
10. 폰틱도 라벨을 고르면 싱글과 같은 툴바(내면·다듬기·커넥터)가 뜸. 폰틱 생성도 크라운과 같이 약 1분.
- 이 계정(Free)은 **3/3 그대로** — 사용자의 "내보내기는 됐어" 는 이 계정이 아님(다운로드 폴더에 덴트버드 파일 없음). 구멍 검사는 STL 받은 뒤.

## 결정·추가 학습 (2026-10-28 저녁)
- **내보내기는 보류**(사용자). 구멍 검사는 STL 이 생기면.
- 같은 케이스로 **싱글-싱글(26·27 따로)** 도 생성함 — 경고 없음, 차감 2.
- **최소 두께 흐름 실측**: 내면 최소 두께를 0.45→1.5 로 올려 적용하니 외형 탭에 "최소 두께 부족" 과 「최소 두께 보정」 단추가 떴고, 누르자 **3초** 만에 경고가 사라짐(진행 표시 없음 — 매크로의 '경고 사라질 때까지 기다리기' 가 맞음). 적용 단추는 **키보드 입력**이어야 풀림(JS 로 value 만 바꾸면 disabled 그대로 — 매크로 _set_number 가 키 입력인 이유).
- **구멍 가설(사용자: "최소 두께쪽에서 구멍이 나는 것 같다")** — 아직 STL 로 확인 못 함. 생각할 수 있는 원인 셋: ① 최소 두께 보정 뒤 교합/인접 조정을 **다시** 하면 그 자리가 또 얇아져 안팎 면이 서로 뚫림(순서는 내면→교합인접→최소두께, 두께가 **맨 뒤**여야 함 — 지금 매크로 순서는 맞음) ② 0.45 가 너무 얇아 보정이 못 메우는 좁은 홈 ③ 조립(합치기) 때 커넥터와 크라운 면이 겹치며 비매니폴드. **확인법**: 구멍 난 STL 을 trimesh 로 `is_watertight`·열린 모서리 위치(교합면인지 커넥터인지 마진인지) 를 봄. **대책 후보**: 두께 보정 뒤 외형 탭 경고 재확인(지금도 함) · 문제 케이스만 최소 두께 0.6 · 우리 쪽 슬라이스 전 `fill_holes` 한 번(slice_job 에 아직 수리 단계 없음 — grep 결과 0).

## 매크로 브릿지 가지 — 붙임 (2026-10-28 밤, 사용자 "매크로에 브릿지 가지 붙여줘")
- dentbird_macro.py: `bridge_span`·`generation_done`(유닛 수만큼 '생성됨'+'생성 중' 없음)·`mark_pontics`·`link_bridge`·`assemble`, `run(..., pontics=)`, `export(..., units=)`(브릿지는 창 항목 "브릿지 a-b" 대조, 창 뜨기 75초), `--pontics`.
- dentbird_params.py: `select_tooth(d, n)`(번호로 이름표 눌러 그 크라운의 막대), `apply_each(d, teeth)`(지대치마다 apply_all — **합치기 전**).
- design_worker.py: "준비 중" Stop 제거. abutments = teeth − pontics. run→apply_each→assemble→export(units=teeth). 떨어진 크라운 둘(24·26)인데 폰틱 없음이면 Stop("…폰틱이 없습니다").
