**2026-08-12 사용자 재확인** — *"기공소는 치과판매가를 절대로 봐서는 안돼.
치과또한 기공원가를 봐서는 안돼 **그 어느 부분에서도**"* (설계서 §8.5)

## 실제로 새고 있던 곳 둘 — 둘 다 확인 후 막음

**① 기공소가 치과 판매가를 봤습니다.**
`prosthesis_types` 조회 정책이 `is_partner_org()` 로 열려 있어 거래 기공소가
`prosthesis_materials` 를 통째로 읽었습니다 — 그 표에 `price`(치과 판매가)가 있습니다.
확인: 기공소 계정으로 **8줄 전부** 보였습니다.

RLS 는 **행** 단위라 열을 못 막습니다. 그래서 값이 빠진 보기를 만들고
원본 표를 닫았습니다 — `prosthesis_products_public`
(`security_invoker = false`). 기공소도 제품 **이름**은 알아야 합니다
(주문서에 'Zir-Cr' 이 찍혀야 뭘 만드는지 압니다).
`getProsthesisCatalog()` 이 세션이 lab 이면 이 보기를 읽고 값은 null 로 옵니다.

**② 기공원가를 안 정한 칸이 치과 판매가로 떨어졌습니다.**
`prosthesis_materials.price` 는 **치과에 파는 값**인데 기공소 쪽도 같은 기본가로
폴백했습니다 — 5만원에 팔고 5만원을 지급하는 셈. 폰틱·핑크에서 실제로 발생.
`resolvePartyPrice(base, override, partyType)` 로 규칙을 빼고 테스트로 잠갔습니다.
**기공소는 `lab_product_costs` 만 씁니다. 안 정했으면 0원이 아니라 '미정'.**

## 확인 방법 (다음에도 이렇게)

각 계정 JWT 로 직접 세어 봅니다. **대조군을 먼저** — 0행이 '막힘' 인지
'원래 없음' 인지 갈라야 합니다.

```
[대조군] 판매가 있는 제품=8, 기공원가 줄=1
[기공소] 제품표=0, 치과별단가=0, 이름보기=8 ✓
[치과]  기공원가=0, 제품표=8 (자기 판매가라 정상)
```

## 잊지 말 것

- 기공소 화면에 값이 필요해지면 **보기에 칸을 더하지 말고** 기공원가에서 가져오세요
- 새 표에 금액을 넣을 때마다 이 양방향 검사를 다시 돌려야 합니다
