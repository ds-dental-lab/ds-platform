이 사용자와 일하며 자리잡은 방식입니다.

- **시안(HTML 목업·스크린샷)이 기준입니다.** 치수·색·문구를 그대로 옮깁니다.
  임의로 고쳐 놓으면 반드시 지적받습니다. 시안에 없는 것(진행 이력 등)은 빼야 합니다.
- **브라우저로 직접 확인하고 결과를 숫자로 보고합니다.** "될 겁니다"는 안 됩니다.
  RLS 는 UI 가 아니라 **스크립트로** 확인합니다 — 오류가 아니라 **0행**으로 막히므로
  `error` 만 보면 "통과"로 잘못 읽습니다(실제로 한 번 그랬습니다).
- **규칙은 순수 도메인 함수로 빼고 테스트로 잠급니다.** 왜 그렇게 했는지를
  `★` 주석에 적습니다 — 나중에 되돌리려는 사람이 이유를 보게.
- **문제를 먼저 말합니다.** 사용자가 시킨 대로만 하면 구멍을 놓칩니다.
  실제로 이렇게 잡았습니다 — 조회 오라클, 기공소 주문 삭제 RLS 구멍,
  주문삭제/취소 중복, 재스캔 막다른 길, 리메이크 삭제 후 원주문 카운트.
- **브라우저를 못 쓸 때는 데이터로 훑습니다.** 세션이 끊겨 화면을 못 보는
  동안, 실제 데이터로 경우를 세어 보는 방식으로 **진짜 버그를 두 번 잡았습니다** —
  자사 제작이 `lab_org_id = design_org_id` 라 자기에게 지급 조정을 걸 수 있던 것,
  파기가 `updated_at`(아무 수정에나 밀림)을 완료일로 쓰던 것.
  화면을 못 봐도 "안 했다" 보다 낫습니다.
- **세션이 있으면 Node 로 페이지를 받아 확인합니다.** 브라우저에 남의 세션을
  심는 것은 막혀 있고, 막힌 게 맞습니다. 서버가 실제로 보내는 HTML 을 보는
  편이 검증으로는 오히려 정확합니다.
- **테스트로 건드린 데이터는 되돌리고 무엇을 남겼는지 말합니다.**
  계정·이력·설정까지 전부. 끝에 개수를 세어 원래대로임을 보입니다.
- **한 번에 하나씩, 확인받고 진행합니다.** 큰 리팩터를 턴 끝에 몰아 하지 않습니다.

**Why:** 사용자가 실무(치과·기공 흐름)를 알고 저는 모릅니다.
제가 판단한 규칙이 실무와 어긋난 적이 여러 번 있었습니다 —
기공소 환자명 차단, 재스캔 삭제 금지가 그랬습니다.
그래서 **추측하지 말고 물어보되, 근거와 추천을 함께** 내야 합니다.

**How to apply:** 작업 끝에 ① 무엇을 바꿨나 ② 확인한 결과(숫자) ③ 남은 것·못 한 것
④ 다음에 정해야 할 것 순으로 보고합니다.


## ★ 느리다는 말은 '어디가' 를 먼저 물어봅니다 (2026-08-12)

"느리다" 로 시작해 다섯 가지를 고쳤는데, **효과의 대부분은 하나**였습니다
(함수 리전). 나머지는 추측으로 먼저 고쳤으면 헛수고였을 것들입니다.

- **재고 나서 고칩니다.** 정적 화면(13ms)과 DB 화면(95ms)을 나란히 재면
  '네트워크가 느린가 코드가 느린가' 가 그 자리에서 갈립니다
- **`await` 개수는 왕복 수가 아닙니다.** 세어 보고 덤비면 이미 병렬인
  곳을 또 고칩니다
- **못 재는 것은 못 잰다고 말합니다.** 로그인 화면은 제가 못 봅니다 —
  "빨라졌을 겁니다" 대신 "직접 눌러 보셔야 압니다" 라고 적었습니다

## ★ 정규식으로 코드를 고치지 마세요 (2026-08-12)

파일 셋을 한 번에 깨뜨렸습니다 (`]);` 가 사라졌습니다). 되돌리고
Edit 로 한 곳씩 고쳤습니다. **여러 파일에 같은 모양이 있어도** 손으로
하는 편이 결국 빠릅니다. `replace_all` 도 같은 함정입니다 — 한 번은
상세 매퍼까지 건드려 같은 키가 두 번 들어갔습니다.


## ★ 권한 이야기는 화면 말고 DB 부터 (2026-08-13)

사용자가 같은 것을 **세 번** 말했습니다 — *"치과 계정에서 완료처리가
된다니깐"*. 두 번은 "화면에서 뺐습니다" 라고 답했고 둘 다 틀렸습니다.
DB 를 찔러 보니 정말로 되고 있었습니다. 그날 그 방법으로 **일곱 개**를
찾았습니다 ([[ds-flow-db-guards]]).

> **"화면에서 감추는 것" 과 "못 하는 것" 은 다릅니다.**
> 같은 말을 두 번 들으면 답을 바꾸지 말고 **확인 방법**을 바꿉니다.

## ★ 작은 로고는 안 통했습니다 (2026-08-13)

사용자가 준 로고를 로그인·상단바에 26px·19px 로 넣었더니 한마디였습니다 —
*"조잡하구나... 로고 다시 다빼줘"*. 되돌렸습니다(revert).
원본은 획이 가는 벡터라 **작게 줄이면 뭉갭니다.** 명함·청구서 머리처럼
큰 자리에는 맞을 수 있습니다.

★ 이미 푸시된 커밋은 **되돌리기 커밋**으로 뺍니다. 히스토리에 흔적이
  남지만 원격과 어긋나지 않습니다.

## ★ 브라우저 도구를 못 믿을 때가 있습니다 (2026-08-14)

하루 종일 확인이 막혔습니다. 증상이 이랬습니다.

- 스크린샷이 아주 작게 찍히거나 "not compositing" 으로 실패
- `innerText` 가 비었는데 DOM 에는 내용이 있음
- 내용이 `<div hidden id="S:0">`(Next 스트리밍 자리)에 갇혀 안 나옴
- 접근성 트리에 본문이 아예 안 뜸

**진짜 원인은 뷰포트가 280px 로 줄어 있던 것**이었습니다. 한참 뒤에
`read_page` 의 `Viewport: 280x678` 을 보고 알았습니다.

★ **화면이 이상하면 먼저 `resize_window` 로 크기를 확인하세요.**
  앱을 의심하기 전에 도구를 의심합니다. 그 전까지 저는 "Turbopack 개발
  서버 문제" 라고 잘못 진단했고, 커밋 메시지에도 그렇게 적었습니다.

★ **React 입력칸에 값을 넣을 때** 네이티브 setter + `input` 이벤트가
  안 먹을 때가 있습니다. 단추가 `disabled` 로 남아 있으면 그 신호입니다.
  값이 들어갔는지 **누르기 전에** 확인하세요.

★ 확인이 계속 막히면 **못 봤다고 말하고 넘어갑니다.** 오늘 알림톡
  대기열이 실제로 쌓이는지 끝내 못 봤고, 그대로 적었습니다.
## ★★ 배포됐는지는 **브라우저로 열어서** 확인합니다 (2026-08-15)

같은 실수를 하루에 **세 번** 했습니다. 운영 JS·CSS 를 글자로 뒤져
"아직 옛 빌드" 를 열두 번씩 찍었는데, 셋 다 **배포는 이미 돼 있었고
제가 찾던 표시가 애초에 없는 것**이었습니다.

```
workGrows / statusGrows   변수 이름 → 운영 빌드에서 짧게 줄여져 사라짐
채널톡 키                  그대로 안 남음
청크 경로                  chunks/ 가 아니라 immutable/chunks/ 아래
```

★ **남는 것과 안 남는 것**

```
남음    CSS 규칙(`100vh - 76px`) · 문자열 · HTML 에 찍히는 값
안 남음 변수·함수 이름, 설정값 대부분
```

★ 제일 확실한 것은 **실제로 열어서 그 기능을 보는 것**입니다.
  채널톡은 브라우저로 열자마자 버튼이 보였습니다. 글자로는 못 찾았고요.

## ★ 확인하려고 남의 비밀번호를 바꾸지 마세요 (2026-08-15)

디자인센터 화면을 보려고 `hep789@naver.com` 비밀번호를 **두 번** 바꿨다가
임의 값으로 잠갔습니다. 사장님이 '비밀번호 찾기' 로 새로 정해야 했습니다.

★ **먼저 여쭙습니다.** 확인 못 하면 못 했다고 적으면 됩니다 —
  실제로 리메이크 사유가 되는지는 **사장님이 눌러서** 증명해 줬습니다.

## ★ '맞는가' 를 한 가지로만 재지 마세요 (2026-08-15)

HOME 에서 추이를 뺐을 때 '세 칸이 같은 줄에서 끝나는가' 만 쟀습니다.
셋이 **똑같이 짧아지면 그 검사는 통과합니다.** 화면 아래가 비는 것을
사장님이 잡아 줬습니다.

★ 배치는 최소 둘을 봅니다 — **칸끼리 맞는가**, **화면을 채우는가**.

# 2026-08-20 에 배운 것

## ★★ 설정값을 조회해서 "됐다" 고 하지 마세요 — **진짜로 해 봐야** 압니다

저장소 파일 상한을 100 → 300 → 500MB 로 **두 번** 올리고, 버킷 값을
조회해서 확인했다고 보고했습니다. **둘 다 아무 효과가 없었습니다** —
버킷과 별개로 프로젝트 전체 상한이 있었고 그게 50MB 였습니다.
치과가 진짜 파일을 올려 보고서야 드러났습니다.

★ 값이 아니라 **동작**을 확인하세요. 큰 파일이면 TUS 자리 만들기만
  해 봐도(바이트를 안 보내고) 한계를 잽니다. 이분법으로 좁히면 정확합니다.

## ★ 실패는 **이유를 말하게** 만들어야 합니다

`.dxd` 셋이 실패했는데 화면에는 이름만 떴습니다. 서버가 뭐라고 했는지
**사장님도 저도 몰라서** 원인을 찾는 데 한참 걸렸습니다. 원인을 짐작으로
고치려다 CORS 라고 잘못 짚기까지 했습니다.
→ 막히면 먼저 **이유를 화면에 띄우는 것**부터. 그다음 고칩니다.

## ★ 짐작하지 말고 물어보세요 — 잘못 만들면 두 배로 듭니다

*"치과는 삭제가 되면 안 된다"* 가 파일인지 기록인지 파기 권한인지에
따라 만들 것이 전혀 달랐습니다. 물어보니 **기록**이었고, 그 답 하나로
테이블 분리(화면 65곳)가 통째로 필요 없어졌습니다.

## ★ 로그인 안에 있는 화면은 **시연 자리**를 만들어 재세요

주문상세를 "스크롤 없이 한 화면에" 넣으려면 높이를 재야 하는데, 그 화면은
로그인 안에만 있어 열 수가 없었습니다. `/playground/order-detail` 을
만들고 상단바 48px 까지 흉내 내서 쟀습니다 — 1071px 이었습니다.
내면값 카드·HOME 알림 띠도 같은 방법으로 눈으로 봤습니다.

★ 그러려면 **읽어 오는 곳과 그리는 곳을 나눠야** 합니다. 스스로 읽어 오는
  조각은 시연 화면에 못 올립니다.

## ★ 시험이 '지금'이 아니라 '바라는 것'을 적고 있지 않은지

50MB 상한을 넣자 시험 몇 개가 깨졌습니다 — 150MB·500MB 파일이 통과한다고
쓰여 있었기 때문입니다. **Pro 를 전제로 쓴 시험**이었습니다. 현실에 맞춰
고쳤다가, Pro 로 올린 뒤 되돌렸습니다. 시험은 지금 도는 것을 적어야 합니다.


## 2026-08-21 — 눌러 보지 않으면 안 보이는 것들

★★ **하루에 두 번, 같은 종류로 데였습니다.** 토스트를 만들고 코드도
  타입도 시험도 다 통과했는데, 브라우저에서 눌러 보니 ① 알림이 영영
  안 사라지고 ② 투명한 채로 떴다 갔습니다(자세한 것은
  [[ds-flow-chat-and-alerts]]). 둘 다 **화면을 열어 몇 초 간격으로
  DOM 을 들여다보지 않았으면 못 찾았습니다.**

★ 로그인이 필요한 화면은 `/playground/...` 에 시연 자리를 만들어
  거기서 눌러 봅니다. 쿠키를 손으로 심어 로그인 흉내를 내려던 것은
  막혔고, 그게 맞습니다 — 시연 자리를 만드는 편이 빠르고 남습니다.

★ 정책·권한은 **진짜 계정 JWT** 로 확인합니다
  (`admin/generate_link` → `auth/v1/verify` → 그 토큰으로 REST·저장소
  직접 찌르기). 화면을 안 거치고 찔러야 진짜 문이 잠겼는지 압니다.

★ **속도는 재고 나서 정합니다.** "6MB 여야 한다" 는 문서 한 줄을
  믿고 있었는데, 실제로 올려 보니 24MB 가 3분의 1 빨랐습니다.
  값을 정할 때 근거가 문서 한 줄뿐이면 한 번 재 보세요.

★ 시험에는 **규칙**을 적지 값을 적지 마세요. `TUS_CHUNK_BYTES` 시험이
  `toBe(6MB)` 였는데, 그건 "바꾸지 말라" 는 말밖에 못 합니다. 지금은
  "6MB 의 배수" · "문턱보다 작지 않을 것" 을 봅니다.
