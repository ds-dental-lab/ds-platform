**2026-08-12 배포.** `https://ds-platform-ten.vercel.app`
자세한 순서는 저장소의 `DEPLOY.md`.

| | |
|---|---|
| 앞단 | Vercel (Hobby) · 프로젝트 `ds-dental/ds-platform` |
| 뒷단 | Supabase `ap-northeast-2` (서울) |
| 함수 리전 | **`icn1`** — 대시보드에서 바꿔야 합니다 (아래) |

**사장님 PC 를 꺼도 돕니다.** `localhost` 는 개발용일 뿐입니다.

## ★ 배포하다 실제로 막힌 것 셋

1. **환경변수를 넣어도 안 먹습니다** — Vercel 은 **빌드할 때** 값을
   코드에 박습니다. 넣고 나서 **재배포**해야 합니다. "Use existing
   Build Cache" 를 켜면 또 안 먹습니다. 확실한 방법은 빈 커밋 푸시:
   `git commit --allow-empty -m "재빌드"` (PowerShell 이라 `&&` 안 됩니다)
2. **`vercel.json` 의 `regions` 가 무시됩니다** (Hobby).
   **Settings → Functions → Function Region** 에서 Seoul 로 바꾸고
   **재배포**해야 적용됩니다.
3. **Supabase → Authentication → URL Configuration** 에 배포 주소와
   `/reset` 을 넣어야 비밀번호 찾기가 삽니다. 안 넣으면 화면은 멀쩡한데
   메일 링크만 죽습니다 ([[ds-flow-password-reset]]).

## ★ 느렸던 원인과 고친 것 (효과 순)

`/privacy` 기준 **800~1400ms → 76~95ms.**

1. **함수가 미국(iad1)에서 돌았습니다.** DB 는 서울인데 질문마다
   태평양을 두 번 건넜습니다. **이것이 거의 전부였습니다.**
   `x-vercel-id` 가 `icn1 → icn1` 이어야 맞습니다
2. **미들웨어(proxy.ts)가 탭 클릭마다 인증 서버에 물었습니다.**
   사이드바 링크 열한 개를 Next 가 미리 읽는데 그 요청도 전부
   미들웨어를 지납니다. `getClaims()` 로 **로컬 서명 검증**(ES256)을
   먼저 하고, 안 풀릴 때만 `getUser()` 로 갑니다 —
   **그 갈래를 없애면 한 시간마다 로그아웃됩니다** (토큰 갱신이 거기서 일어남)
3. **`loading.tsx` 가 하나도 없었습니다.** 누르면 서버가 다 그릴 때까지
   화면이 멈춰 있어 사람이 또 누릅니다. 체감의 정체였습니다
4. **`getSession()` 을 한 페이지에서 여러 번** 불렀습니다(66곳).
   React `cache` 로 요청당 한 번
5. **줄 세운 조회들** — 휴일이 네 화면에서 맨 뒤에 혼자 기다렸고,
   정산 상세는 5단계였습니다(→2단계). 열람 기록은 `after()` 로
   응답 뒤로 보냈습니다

★ `await` 개수와 왕복 수는 **다릅니다.** 주문상세는 await 이 여럿이지만
  실제 왕복은 1회입니다 — 세션은 캐시되고 기록은 응답 뒤로 갔습니다.

## 캐시는 함부로 못 겁니다

임플란트 목록만 `unstable_cache` 했습니다 (`using (true)` 라 누구에게나
같음). **제품·휴일은 안 했습니다** — 조직마다 다르고, 제품은 기공소에게
가격을 뺀 판을 줍니다. 캐시는 여러 요청이 함께 쓰는 서랍이라 거기 넣으면
남의 것이 갑니다 ([[ds-flow-price-isolation]]).

★ Next 16 은 `revalidateTag` 가 아니라 **`updateTag`** 입니다.
  revalidateTag 는 '언젠가 새로 읽어라' 라서 방금 고친 사람이 옛 목록을
  봅니다. 타입 검사가 잡아 줬습니다.

## ★ 도메인 `denflow.kr` — **붙었습니다** (2026-08-14, 가비아)

```
https://denflow.kr       200  <title>DenFlow</title>   ← 정본
https://www.denflow.kr   308 → https://denflow.kr/
x-vercel-id: kix1::icn1   (함수는 서울)
```

넣은 값: `A @ 216.198.79.1` · `CNAME www e603bc396fd81d0b.vercel-dns-017.com.`

★ **CNAME 대상이 프로젝트마다 다릅니다.** 예전의 `cname.vercel-dns.com`
  이 아니라 프로젝트 고유 문자열을 내줍니다(옛 값도 아직은 돕니다).
  **문서에 IP·CNAME 을 적어 두고 재사용하면 안 됩니다** — 화면 값이 정본.

★ Vercel 추가 창의 체크박스가 함정입니다. `Include apex and www variants`
  가 켜져 있으면 www 를 넣을 때 apex 도 딸려 들어와
  *"A domain cannot redirect to itself"* 로 막힙니다. **꺼야 합니다.**
  apex 와 www 를 다르게 쓰려면 **두 번 나눠** 넣습니다.

★ 사기 전/후를 DNS 로 구별할 수 있습니다 — 미등록은 NXDOMAIN,
  등록됐는데 존이 안 열렸으면 SERVFAIL, 열리면 정상.

★ Supabase 인증 주소도 **2026-08-14 에 바꿨습니다** (Site URL =
  `https://denflow.kr`, 허용목록에 `https://denflow.kr/**`).
  옛 `.vercel.app/reset` 줄은 일부러 남겼습니다.

### ★★ 인증 주소가 제대로 들어갔는지 확인하는 법

대시보드 말고 **밖에서 확인할 수 있습니다.** 메일은 안 나갑니다 —
`admin/generate_link` 는 링크를 만들기만 합니다.

```
POST {SUPABASE_URL}/auth/v1/admin/generate_link
     apikey + Authorization: Bearer <service_role>
     { "type":"recovery", "email":"<있는 계정>", "redirect_to": ... }
→ action_link 의 ?redirect_to= 를 봅니다
```

| 넣은 값 | 나와야 하는 것 |
|---|---|
| 안 줌 | **Site URL** 그대로 |
| 허용된 주소 | 그 주소 그대로 |
| 허용 안 된 주소 | **Site URL 로 되돌아감** ← 문지기가 사는 증거 |

★ 세 번째가 핵심입니다. 허용목록에 없으면 **오류가 아니라 조용히 딴
  곳으로** 갑니다. 도메인을 바꾸고 이걸 빠뜨리면 화면은 멀쩡한데
  메일 링크만 죽는 이유가 이것입니다 ([[ds-flow-password-reset]]).

개명 전에 `dsflow.kr` 로 정했다가, 이름이 DenFlow 가 되면서 다시
정했습니다. 저장소에 주소를 박아 둔 코드는 **한 곳도 없습니다** —
비밀번호 찾기의 `redirectTo` 도 `window.location.origin` 이라 열린
주소를 따라갑니다(전체 훑어 확인). **재배포도 필요 없습니다.**

★ **DNS 로 상태를 구별할 수 있습니다.** 안 산 `.kr` 은 NXDOMAIN
  (`DNS name does not exist`), 산 뒤 네임서버가 아직 답을 안 하면
  SERVFAIL(`DNS server failure`) 입니다. 2026-08-14 기준 SERVFAIL —
  **등록은 됐고 레코드가 아직 안 들어간 상태**입니다.

붙이는 순서와 가비아 화면 위치는 `DEPLOY.md` **7절**에 다 적어 뒀습니다.
요점 셋: ①Vercel 에서 값을 **먼저** 받는다 ②가비아 CNAME 은 **끝에 점**
③네임서버는 **가비아 것 그대로** 둔다(나중에 메일 SPF·DKIM 때문).

★ **주소를 바꾸면 Supabase → Authentication → URL Configuration 을
  같이 고쳐야 합니다.** 안 하면 화면은 멀쩡한데 **메일 링크만 죽습니다** —
  비밀번호 찾기와 가입 확인 메일이 통째로 깨집니다.

★ vercel.app 이름만 먼저 바꾸는 것은 권하지 않습니다. 그 URL 설정을
  두 번 하고 거래처에도 두 번 알려야 합니다. 어차피 도메인이 있어야
  발송 서비스가 붙습니다.

```
버킷 상한          storage.buckets.file_size_limit  ← 마이그레이션으로 고침
프로젝트 전체 상한   대시보드 → Storage → Settings   ← 무료는 50MB 고정
                                                     둘 중 낮은 쪽이 이깁니다
```

★ **버킷만 올리는 것은 아무 효과가 없습니다.** 실제로 100 → 300 → 500MB
  로 두 번 올렸는데 둘 다 소용없었고, **치과가 진짜 파일을 올려 보고서야**
  알았습니다. 버킷 값을 조회해서 "됐다" 고 판단한 것이 잘못이었습니다.

★ **다음에 상한을 올릴 때는 진짜 파일 크기로 자리 만들기를 해 보세요.**
  TUS 의 `POST /storage/v1/upload/resumable` 에 `upload-length` 만 넣어
  보면 바이트를 안 보내고도 알 수 있습니다 — 이분법으로 좁히면 정확한
  한계가 나옵니다. 그렇게 재서 50.00MB 를 찾았습니다.
