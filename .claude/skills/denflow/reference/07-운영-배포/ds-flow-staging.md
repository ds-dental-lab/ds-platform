## ★ 어디를 보고 있는지 화면이 말해 줍니다

이걸 만든 이유가 전부입니다 — **localhost 를 시험으로 여기고 청구서를
발행했습니다.** 주소만 보고는 구별할 길이 없었습니다.

- `npm run check-env` 첫 줄에 **프로젝트 ref 를 그대로** 찍습니다.
  운영이면 크게 알립니다 (열쇠가 아니라 주소라 로그에 남아도 됩니다)
- 화면 맨 위 **주황 띠**(`EnvBadge`). `NEXT_PUBLIC_ENV_LABEL` 이 있을 때만
  그립니다 — **운영에서는 아무것도 안 보입니다.** 띠를 운영에 두르면
  거래처가 보고, 며칠이면 눈에 안 들어옵니다
- 3px 라 화면을 안 밀고 `pointer-events-none` 이라 단추를 안 막습니다

★ 로컬이 운영을 볼 때는 `.env.local` 에 `NEXT_PUBLIC_ENV_LABEL=★ 운영 DB`
  를 넣어 둡니다. 조용한 것보다 시끄러운 편이 낫습니다.

## 심는 순서 (다시 세울 때)

```bash
npm run seed-staging                   # 버킷 + 계정 셋
npx supabase db push --include-seed    # 마이그레이션 + 조직·제품
npm run seed-staging-data              # 단가 + 주문 8건 + 수거요청
```

★ **셋 다 운영이면 첫 줄에서 멈춥니다.** ref 를 먼저 봅니다. 가짜 주문을
  운영에 넣는 것이 이 스크립트로 낼 수 있는 최악의 사고입니다.
★ 주문이 이미 있으면 아무것도 안 합니다 — 두 번 돌려도 안 불어납니다.
★ 시험 계정 셋 다 비밀번호 `test1234`.

## ★ 나누자마자 찾은 것 — 마이그레이션만으로는 못 세웁니다

빈 프로젝트에 66건을 올리니 **63번째에서 멈췄습니다.**

```
ERROR: function can_access_order(uuid) does not exist
```

두 마이그레이션(저장소·알림)이 이 함수를 쓰는데 **만드는 마이그레이션이
없었습니다.** 운영에는 예전에 손으로 만들어 둔 것이 남아 있어 여태 안
터졌습니다. **재해 복구가 안 되는 상태였는데 아무도 몰랐습니다.**

★ 정의를 **지어내지 않았습니다.** 보안 함수라 한 글자만 틀려도 문이
  넓어집니다. 치과 계정의 **진짜 JWT 로 운영의 함수를 직접 불러** 대조했습니다 —
  내 주문 true · 남의 주문 false, 인자 이름 `target_order`.

★ 타임스탬프도 한 번 틀렸습니다. `0814` 로 뒀더니 새 환경에서는 여전히
  63번째에서 터집니다(적용이 이름 순). **쓰는 것보다 앞으로** 당겨야 합니다
  (`20260813165000`).

## 도구에서 막힌 것

- `supabase link` 가 스키마 오류로 실패 → **`npx supabase@latest`** 로 해결
- `supabase db dump` 는 **Docker 가 필요**합니다. 이 PC 에 없어서 못 씁니다
- 운영에 뒤늦은 마이그레이션을 올릴 때는 **`db push --include-all`**

## 남은 것

- **미리보기 배포를 눈으로 못 봤습니다.** 주소 규칙을 못 맞혔고(팀 슬러그)
  Vercel CLI 는 로그인이 안 돼 있습니다. 사람이 한 번 열어 `preview` 띠와
  `design@test.kr` 로그인만 확인하면 끝납니다
- 브랜치를 새로 만들 때 **커밋이 master 와 같으면 미리보기가 안 생깁니다** —
  Vercel 이 같은 SHA 를 다시 안 빌드합니다. 빈 커밋 하나면 됩니다
