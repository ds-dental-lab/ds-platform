**2026-08-15.** *"기공소는 실제 가공작업 할때 박스에 해당 환자분
기공의뢰서 용지를 뽑아서 정보를 구분짓거든"*.

## 무엇이 어디에

```
종이     components/order/WorkOrderSheet     두 자리가 같이 씁니다
단추     components/order/WorkOrderButton    주문상세 머리줄, 요청시한 앞
화면     /design/orders/[id]/work-order
         /lab/orders/[id]/work-order
규칙     canPrintWorkOrder (domain/order-status)
```

담긴 것: 주문번호 · 환자명 · 치과 · 기공소 · 주문일 · 요청시한 ·
치식도 · 제작보철 · 임플란트 규격 · 제작옵션 · 요청사항 · **작업 메모(빈 칸)**

## ★★ 금액이 한 줄도 없습니다

기공소와 치과가 같이 볼 수 있는 종이인데, 기공단가와 치과 판매가는
서로 못 보는 값입니다 ([[ds-flow-price-isolation]]).
**종이는 화면보다 더 잘 돌아다닙니다 — 박스에 붙어 치과까지 갑니다.**
여기 금액을 실으면 그 격리가 통째로 무너집니다.
렌더링 결과에 `₩`·`원`·수가 문자가 없는 것을 확인했습니다.

## 누가 뽑나

**자리로만** 가릅니다 — 기공소·디자인센터 **전원**(관리자·사용자 구분
없음). 실제로 종이를 뽑는 사람은 작업대에 있는 사용자입니다.
치과는 뺐습니다 — 작업 지시서라서, 사용자가 요청한 넷에도 없었습니다.

★ 화면에서 감추는 것과 주소를 막는 것은 다릅니다. 인쇄 화면도 같은
  규칙으로 막습니다(`notFound`). 주소는 복사해서 돌아다닙니다.

## ★ 클릭 한 번 — 안 보이는 틀로 인쇄

```
전  기공의뢰서 → (새 창) → 인쇄/PDF → 인쇄   세 번
후  기공의뢰서 → 인쇄                        한 번
```

숨은 iframe(`?bare=1`)에 담아 거기서 `print()` 를 부릅니다. 보던 주문
화면이 그대로 있어 새 창을 닫고 돌아올 필요가 없습니다 — 기공소는
이걸 하루에 수십 번 합니다.

- `?bare=1` 이면 '주문으로 / 인쇄' 단추를 안 그립니다 (종이 첫 줄에 찍힘)
- 못 되면 **새 창으로 물러섭니다.** 아무 일도 안 일어나면 버튼이 고장 난
  줄 압니다 — 종이를 못 뽑는 것이 이 화면에서 제일 나쁜 일입니다
- `afterprint` 로 치우고, 그 신호를 안 보내는 브라우저용으로 뒤늦게 한 번 더

## ★★ 곁다리로 찾은 것 — 인쇄 규칙이 아예 없었습니다

상단바·사이드바가 `fixed` 인데 `@media print` 가 한 줄도 없어서,
뽑으면 **종이 첫 장에 그대로 찍힙니다.** 기공의뢰서만이 아니라
**청구서도 그때까지 그 상태였습니다.**

`globals.css` 에 규칙을 넣고 껍데기에 표시를 달았습니다:

```
[data-screen-only]  인쇄할 때 사라짐  (header · nav · EnvBadge)
[data-print-area]   껍데기가 비워 둔 자리를 되돌림 (main)
```

★ 구조(`body > div > header`)가 아니라 **표시로** 고릅니다. 구조로 고르면
  껍데기를 한 겹만 더 감싸도 조용히 안 먹는데, **그런 고장은 종이를
  뽑아 보기 전까지 아무도 모릅니다.**

★ 사용자가 청구서까지 확인했습니다 — 둘 다 사이드바 안 나옵니다.

## A4 한 장 (2026-09-21, 사용자 요청)
- 전: 치식도(~960px)가 폭을 넘쳐 스크롤바 + 종이에서 24~28·35~38 잘림, 임플란트 규격이 치아마다 한 줄(17줄)이라 둘째 장.
- 고침: `FitWidth`(zoom 으로 폭에 맞춤, beforeprint 때 다시 잼) · 규격은 **같은 규격끼리 한 줄 + 치아 목록** · 여백 축소 · `@page work-order {A4; margin 0}` + 종이 안 여백 9/11mm(이름 붙은 페이지라 다른 인쇄물 영향 없음, 브라우저 머리글·주소 안 찍힘).
- 확인: ORD-260920-001(치아 30여 개, 임플란트 17) 을 로컬에서 PDF 로 → 1장.
- ★ 1차(FitWidth 만)는 **실제 인쇄에서 잘림** — 인쇄 단추가 1px 숨은 iframe 에서 print() 해 폭을 못 잼. 인쇄는 CSS 고정 zoom 0.68(치식도 실측 988px, 가용 ≈710px). 시험은 반드시 뷰포트 1px 로 흉내 내서 PDF (커밋 뒤).
