**2026-08-12 만들었다가 같은 날 되돌렸습니다.**
사용자 — *"파일명은 나오게끔 다시 만들어주고 / 인증 관련부분은 나중에하고
일단 홈페이지 구성 완성도부터 다시 하자"*.
지금은 **원본 파일 이름이 그대로 보입니다.**

## 되살릴 수 없는 것

마이그레이션이 있던 18줄의 `file_name` 을 덮어썼고 **원본을 어디에도 안
남겼습니다** — 그게 그 마이그레이션의 목적이었으니까요. 저장소 경로도
처음부터 uuid 라 거기서도 못 꺼냅니다. 그 18줄은 영영 `ORD-…_스캔1.obj` 입니다.
(전부 테스트 자료였습니다. 앞으로 올리는 것은 원래 이름 그대로.)

## ★ 다시 하게 되면 — 원본을 지우지 마세요

되돌릴 수 있어야 합니다. `file_name` 은 그대로 두고 **보여 줄 이름을 따로**
두는 편이 낫습니다. 그러면 마음이 바뀌어도 한 줄도 안 잃습니다.
(대신 원본이 표에 남으므로, 기공소가 그 칸을 못 읽게 하려면 값 빠진 보기가
필요합니다 — [[ds-flow-price-isolation]] 과 같은 방법.)

## 그때 정한 것들 (되살릴 값어치가 있는 판단)

- 이름은 `ORD-260811-013_스캔1.obj`. 주문번호가 앞 — 기공소는 여러 주문
  파일을 한 폴더에 받아 두고, 그때 제일 먼저 필요한 게 어느 주문인지입니다
- **치식은 절대 안 넣습니다.** `2026-08-11-박나래-26.obj` 의 `26` 은 치식
  같지만 `2026`·`08`·`11` 도 두 자리입니다. 이름만 보고는 못 갈라냅니다.
  **틀린 치식이 적힌 파일은 이름 없는 파일보다 위험합니다** —
  기공소가 그걸 믿고 다른 이를 만듭니다
- 번호는 개수가 아니라 **쓰인 번호**로 셉니다 (지운 자리를 다시 쓰면 중복)
- 트리거 안에서는 번호를 세면 안 됩니다 — 한 문장으로 여러 줄을 넣을 때
  형제 줄이 아직 안 보여 전부 같은 번호가 됩니다
- 이름을 바꾸면 **빠진 파일 짝 맞추기가 깨집니다.** 줄에 남은 건 지은
  이름이고 사람이 고르는 건 원본이라 영영 안 만납니다 → 크기+확장자로

전부 커밋 **2591e71** 에 있습니다 (되돌린 것은 e6e2cc2).

## 왜 하려 했었나 (문제 자체는 그대로입니다)

스캔 파일 이름에 환자 이름이 있었습니다 — 열여덟 개 중 열세 개.
저장소 경로는 진작 뗐지만 표시용 이름이 원본이라, 기공소가 내려받으면
그 이름 그대로 PC 에 저장됩니다. 열람기록·보관기간·파기가 안 닿는 곳으로.
