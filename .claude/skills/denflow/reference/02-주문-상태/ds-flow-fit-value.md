**2026-08-17.** *"치과마다 원하는 수치값이 다르기 때문에 작업 시 수시로
변하는 내면값을 확인해야 하거든"*

보철이 치아에 얼마나 헐겁게(시멘트 갭) · 옆니와 얼마나 꽉(컨택) 앉을지를
치과 원장 취향대로 적어 두는 표입니다. 디자이너가 주문을 열 때마다 봅니다.

## 무엇이 어디에

```
규칙     domain/fit-value        필드 목록·검사·형식·변경 비교가 한 곳에
표       clinic_fit_values       치과 조직에 한 줄 (주문마다가 아님)
이력     fit_value_changes       '자연치 0.02 → 0.04' 를 말로 굳혀 둠
관리탭   /design/fit-values      관리자만 — 값을 **정하는** 자리
카드     주문상세 치과명 클릭     디자이너·관리자 모두 — 값을 **쓰는** 자리
```

칸: 자연치 · CNC · Inlay · PLA · PMMA(재료) / 맞결 · 단일(컨택) /
Hook · 임플란트 · **비고**

★ **주문마다가 아니라 치과에 한 줄**입니다. 주문에 붙이면 치과가 취향을
  바꿨을 때 지난 주문 수백 줄을 고쳐야 합니다.

★ **필드 목록이 도메인 한 곳에** 있습니다. 표·창·카드·이력 넷이 같은
  필드를 그리는데, 목록이 화면마다 있으면 하나는 반드시 빠뜨립니다.

★ 등록 여부는 **줄 유무가 아니라 값 유무**입니다. 줄로 가르면 '한 번
  열어 본 치과' 가 전부 등록으로 보입니다.

## ★ "바뀌면 알린다" 는 이렇게 풀었습니다

종을 울리면 지나가고 없어집니다. 대신 —

```
① 저장이 곧 기록    바뀐 것을 문장으로 이력에 굳힘 (이력이 안 남으면 저장도 실패)
② 치과명 옆 주황 점  7일. 주문을 열 때마다 보므로 볼 때까지 남습니다
③ 카드 맨 위 주황 띠 '8월 16일에 내면값이 바뀌었습니다'
```

★ **무엇이 바뀌었는지는 안 늘어놓습니다** (2026-08-19 요청).
  변경 목록을 카드에 넣었더니 정작 지금 값이 뒤로 밀렸습니다. 디자이너가
  볼 것은 '지금 이 치과는 얼마인가' 이고, 바뀐 값은 바로 위에 새 값으로
  떠 있습니다. 이력은 DB 에 그대로 쌓입니다 — 화면에서만 뺐습니다.

## 비고 = 손으로 적는 치과 특징

카드에서 제일 넓은 자리를 줍니다. 수치는 표로 읽지만 이 치과가 어떤
곳인지는 글로만 남습니다. 비어 있어도 자리를 냅니다 — '아직 적힌 내용이
없습니다' 가 보여야 채웁니다. 관리탭 표에도 칸을 세웠습니다.

★ 수정 창에 **회색 예시 글을 한 칸도 안 깝니다** (2026-08-19 요청).
  빈 칸과 적힌 칸이 한눈에 갈려야 합니다. 무엇을 넣는 자리인지는
  칸마다 붙은 이름표가 말합니다.

## 문지기

보기는 디자인센터 **전원**, 고치기는 **관리자만**, 치과·기공소는 0줄.
화면이 아니라 RLS(`fit_select` / `fit_write`)가 막습니다.

확인 (운영·진짜 JWT 셋): 관리자 쓰기 ✓ · 디자이너 읽기 ✓/쓰기 0줄 ·
치과 0줄 · 이력은 관리자도 못 지움.
