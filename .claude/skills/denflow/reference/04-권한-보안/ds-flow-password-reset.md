**2026-08-12 요청.** *"로그인창 회원가입 옆에 비밀번호 찾기도 필요해보여.
가입한 이메일로 인증번호 발송해서 확인버튼 누르거나 입력하면 새비밀번호
입력할수 잇게"*

`/reset` — 한 화면에서 이메일 → 인증번호 → 새 비밀번호 → 끝.
규칙은 `domain/password-reset` (테스트 23개).

## ★ 링크가 아니라 번호입니다

Supabase 가 기본으로 주는 것은 눌러서 들어오는 링크인데, **메일을 연
기기에서만** 됩니다. 병원 컴퓨터에서 로그인하려는데 메일은 휴대폰에 와
있는 일이 흔합니다. 번호는 눈으로 옮겨 적을 수 있습니다.

## ★ 자릿수를 박으면 안 됩니다 — 실제로 데었습니다

6자리로 만들었다가 **진짜로 받아 보니 8자리**였습니다 (Supabase 설정,
6~10). 그대로 뒀으면 맞는 번호를 들고도 칸에 다 못 넣어 **영영 못
들어갑니다.** `MIN_CODE=6 / MAX_CODE=10` 범위로 받고, 화면에서도
"몇 자리" 라고 단정하지 않습니다.

→ 화면을 만들면 **실제로 한 번 돌려 봐야** 이런 게 잡힙니다.
   `admin.generateLink({type:'recovery'})` 가 메일 없이 번호를 줍니다.

## ★ 들어오는 길이 둘입니다 — 번호 또는 링크

템플릿에 `{{ .Token }}` 을 **못 넣었습니다** (2026-08-12, 사용자:
*"토큰 못넣엇어 입력이안되네"*). 프로젝트에 따라 그 칸이 안 열립니다.
그래서 **기본 메일에 이미 들어 있는 링크**로도 같은 자리에 닿게 했습니다.
설정을 못 고쳐도 오늘 됩니다. 나중에 토큰을 넣으면 번호 쪽도 살아납니다.

링크는 `/reset` 으로 돌아오고, 그 화면의 ③(새 비밀번호)부터 이어집니다.
따로 페이지를 만들면 같은 화면이 두 벌 됩니다.

### ★★ `@supabase/ssr` 은 flowType 을 'pkce' 로 못박아 둡니다

`createBrowserClient` 에 `flowType: 'implicit'` 을 넘겨도 **조용히
무시됩니다.** 그래서 링크로 돌아와도 주소(`#access_token=…`)를 아무도
안 읽고, 화면은 멀쩡한데 첫 칸에 그대로 서 있었습니다. 한참 헤맸습니다.

→ 비밀번호 찾기만 **순정 `@supabase/supabase-js`** 를 씁니다
  (`createRecoveryClient`). `flowType: 'implicit'` +
  `detectSessionInUrl: true` + `persistSession: false`.

**PKCE 를 쓰면 안 되는 이유이기도 합니다.** PKCE 는 링크를 *요청한 그
브라우저*에 남은 쪽지(code verifier)가 있어야 열립니다 — 병원 컴퓨터에서
눌렀는데 메일은 휴대폰에 오는, 바로 그 경우가 막힙니다.

★ 세션을 저장하지 않으니 **연결 하나를 끝까지** 써야 합니다. 걸음마다
  새로 만들면, 인증까지 해 놓고 저장하려는 순간 방금 인증한 사람에게
  "로그인이 필요합니다" 가 뜹니다.

발송 자체는 아직 Supabase 기본 발송함이라 시간당 몇 통으로 막힙니다
([[ds-flow-backlog]] 의 도메인·발송 서비스).

## 만들면서 지킨 것

- **그 이메일이 있는지 없는지 말하지 않습니다.** "가입되지 않은
  이메일입니다" 는 남의 가입 여부를 확인해 주는 창구가 됩니다
- **바꾼 뒤 로그아웃합니다.** 인증하는 순간 이미 로그인 상태가 되는데,
  그대로 들여보내면 **새 비밀번호가 진짜 되는지 아무도 확인 안 한 채**
  넘어갑니다
- 새 비밀번호는 **두 번** 받습니다 — 한 번이면 오타가 그대로 새
  비밀번호가 되고, 그 순간 방금 바꾼 것으로도 못 들어옵니다
- 붙여넣은 번호의 공백·하이픈을 걷어냅니다. 그걸로 "맞지 않습니다" 를
  띄우면 사람은 자기가 잘못 본 줄 압니다
- 재발송 60초 잠금

확인: 틀린 번호 막힘 · 맞는 번호 통과 · 새 것으로 로그인 됨 · 옛 것 막힘 ·
**쓴 번호 재사용 막힘**. 시험 계정은 지웠습니다.

## 인증 서버 쪽 규칙을 조였습니다 (2026-08-21)

Supabase Authentication → Providers → Email 에서 사장님이 켰습니다.

- **Minimum password length 6 → 8.** ★ 우리 화면은 이미 8을 요구하는데
  (`MIN_PASSWORD = 8`) DB 는 6이었습니다. 규칙이 두 군데 있으면
  **느슨한 쪽이 실제 규칙**입니다 — 화면을 안 거치면 7자리도 들어갔습니다.
- **Prevent use of leaked passwords → ON.**

**안 건드린 것과 이유**
- `Require current password when updating` — 켜면 비밀번호 **찾기**가
  깨집니다. 잊어서 온 사람에게 지금 비밀번호를 물어보는 셈입니다.
- `Password requirements`(대소문자·숫자·기호) — 켜면 **관리자가 계정
  만들 때 나오는 임시 비밀번호가 막힙니다.** 우리 것은 헷갈리는 글자
  (0·O·1·l·I)를 뺀 영숫자 10자 + `!7` 이라 대문자가 안 뽑히는 경우가
  있습니다. 그러면 계정 생성이 그 자리에서 실패합니다.
- `Email OTP expiration 3600초` 유지 — 치과는 메일을 늦게 봅니다.

**버리는 계정으로 확인** (`zz-pwtest-…@denflow-test.invalid`, 만들고 지움)

| 넣은 값 | 결과 |
|---|---|
| `Ab3d5f7` (7자리) | 422 `Password should be at least 8 characters` |
| `password` · `password123` · `qwerty12` | 422 `known to be weak and easy to guess` |
| 우리 임시 비밀번호 20개 | **전부 통과** |

## ★ 그래서 화면 문구를 갈랐습니다

차단을 켜니 **"흔한 비밀번호"가 흔한 길**이 됐습니다. 그런데 화면은
무엇이 잘못됐든 "비밀번호를 바꾸지 못했습니다. **처음부터 다시 해
주세요**" 하나였습니다 — 다른 것을 지으면 될 일로 인증번호부터
다시 받게 한 것입니다.

`passwordSaveFailure(raw)` (domain/password-reset) 가 가릅니다:
- 흔함·유출 / 쓰던 것과 같음 / 짧음 → `retry: true`, 그 칸에 머무름
- 그 밖(세션 끊김 등) → 처음부터

★ 인증 서버의 말은 영어입니다. 그대로 새지 않는지 시험이 봅니다
  (`not.toMatch(/[a-z]{4,}/)`).

★ 새로 안 것 하나 — GoTrue 는 **쓰던 것과 같은 비밀번호**도 막습니다
  (`New password should be different from the old password`).
  이건 대시보드 설정이 아니라 기본 동작입니다.


## 메일 템플릿 — 저장소에 있습니다 (2026-08-21)

`supabase/email-templates/` (recovery.html · confirmation.html · README.md)
붙이는 곳: Authentication → **Emails** → Reset Password / Confirm signup.
제목도 함께 바꿉니다.

★★ **기본 템플릿에는 인증번호가 없었습니다.** SMTP 를 붙이고 메일이
  도착했는데 영어에 링크 하나뿐이었습니다 — 우리 화면은 **번호**를
  넣는 방식이라, 받고도 넣을 것이 없는 상태였습니다.
  `{{ .Token }}` 을 크게 싣고 링크는 아래에 남겼습니다(두 길 다 받습니다).

★ 가입 확인은 **링크가 맞습니다** — 번호 넣는 화면이 없습니다.
  대신 '누른 뒤에도 승인이 남아 있다' 를 메일에서 말해 줍니다.

★ 안 쓰는 항목 — Magic Link · Invite user · Change Email.
  계정은 디자인센터가 사용자탭에서 직접 만듭니다.

**메일 HTML 에서 지킬 것**
- 그림 금지. 메일 프로그램이 SVG 를 지웁니다 — 로고는 **글자로** 그립니다
- flex·grid 안 됩니다. **표(table)** 로 짭니다
- **폭을 박지 마세요.** `width="100%"` + `max-width:560px`.
  560 으로 박았다가 좁은 화면에서 잘렸습니다 — 메일은 휴대폰으로 더 봅니다
- 색은 로고와 같게: 남색 `#16324F` · 청록 `#14B8A6` · 파랑 `#1279E8`

★ 보기는 **`/playground/email`**. 대시보드에 넣고 확인하지 마세요 —
  그때마다 한 통씩 나가고 한도가 시간당 30통입니다.


## 유출 비밀번호 문구 (2026-09-05)

사장님이 폰 가입 시험 중 '유출된 적 있는 비밀번호' 를 만나고 **"에러가
뜬다"** 고 함 — 막은 게 맞음(8/21 켠 차단). 문구에 **통과하는 법 한 줄**
("단어 두 개에 숫자 — 예: 사과나무2026") 붙임.
★ 문장은 `domain/password-reset` 의 `LEAKED_PASSWORD_MESSAGE` 한 곳.
  가입(signup)도 여기서 가져다 씀 — 전엔 두 파일에 따로 있었음.
