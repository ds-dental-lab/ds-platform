# SPEC — 쉐이드 포토 (MVP)

> 이 문서는 `prototype/shade-photo-prototype.html`과 한 쌍이다.
> 프로토타입이 "어떻게 보이고 움직이는가", 이 문서가 "왜 그렇고 뒤에서 무엇이 일어나는가"를 정의한다.
> 충돌 시 이 문서가 우선하며, 문구·레이아웃은 프로토타입이 우선한다.

---

## 1. 핵심 원칙

1. **분류가 필요 없는 구조**: 사진은 촬영 시점에 이미 의뢰서(Case)에 귀속된다. "찍고 나서 어디 보낼지 고르는" 카톡 모델을 뒤집는다.
2. **원본 보존**: 업로드 이미지는 재압축·리사이즈 없이 원본 그대로 저장한다. 목록용 섬네일은 서버에서 별도 생성한다.
3. **3초 플로우**: 스태프 기준 [홈 열기 → 첫 항목 탭 → 촬영]이 3탭 이내여야 한다. 오늘 작성된 의뢰가 리스트 최상단에 온다.
4. **안전망 우선**: 바쁜 진료실에서는 어떤 절차도 건너뛸 수 있어야 한다. 미분류 촬영 → 나중에 매칭 경로를 항상 제공한다.

---

## 2. 사용자 플로우

### 2-A. 기본 플로우 (의뢰서 선택 → 촬영)
```
[홈: 오늘 의뢰 목록]
  └─ 환자 탭
[케이스 상세] 환자명/보철종류/치식/기존 첨부 사진
  └─ "쉐이드 촬영" 탭
[카메라] 가이드 오버레이 + 컷 체크리스트(①쉐이드가이드 포함 ②정면)
  └─ 셔터 n회 → "첨부 n" 탭
[완료] "OOO 의뢰서에 사진 n장이 원본 화질로 첨부됐어요.
        덴플로우 치과기공소에 알림을 보냈습니다."
  └─ [오늘 의뢰로 돌아가기] / [추가 촬영]
```

### 2-B. 미분류 플로우 (촬영 먼저)
```
[홈] 하단 FAB "바로 촬영 · 나중에 분류" 탭
[카메라] (헤더에 "미분류 촬영" 표기)
  └─ 셔터 n회 → "첨부 n" 탭
[매칭] "어느 의뢰서에 첨부할까요?" — 최근 의뢰서 순 리스트
  ├─ 의뢰서 탭 → [완료]
  └─ "나중에 분류" 탭 → 홈 복귀 + 토스트 "미분류함에 n장 보관됨"
```

### 2-C. (2단계) 알림톡 딥링크
데스크에서 의뢰서 저장 시 등록된 스태프 폰으로 카카오 알림톡 발송:
"김OO님 의뢰서 생성 — 쉐이드 촬영하기 [링크]"
링크는 해당 Case의 카메라 화면으로 바로 진입하는 딥링크. MVP 1단계에서는 웹푸시로 대체 가능.

## 3. 화면 명세

### S1. 홈 (오늘 의뢰 목록) — 진료실 모바일의 시작 화면
- 헤더: denflow 로고(좌) + 치과명 배지(우), 타이틀 "쉐이드 촬영", 서브 "환자를 선택하면 사진이 해당 의뢰서에 자동 첨부됩니다"
- 검색바: 환자명 검색, **한글 초성 검색 지원** (예: "ㄱㅁㅅ" → 김민서)
- 리스트: 날짜 섹션("오늘 · 8월 21일 (금)" / "어제 …")으로 그룹핑, 최신 작성 순
  - 케이스 카드: 치아 아이콘 / 환자명 / `보철종류 · 치식 · 작성시각` / 상태 칩
  - 상태 칩: `쉐이드 대기`(주황 계열 #FEF3E2/#B45309), `촬영 완료`(민트 #EAF6F4/#0E9384)
- 하단 고정 FAB: "바로 촬영 · 나중에 분류" (네이비 배경)
- 표시 범위: 최근 7일. 그 이전은 검색으로만 접근

### S2. 케이스 상세
- 뒤로가기("오늘 의뢰"), 환자명 크게
- 메타: 의뢰 내용 / 작성 시각·치과명 / 담당 기공소
- "쉐이드 사진" 섹션: 첨부 섬네일 그리드. 없으면 점선 빈 박스 "아직 없음"
- 하단 고정 버튼: "쉐이드 촬영" (티일 배경) → 카메라 진입

### S3. 카메라
- 실기기 카메라 사용: `navigator.mediaDevices.getUserMedia` (후면 카메라, 최대 해상도)
- iOS Safari PWA의 getUserMedia 제약 확인 필요. 문제 시 `<input type="file" capture="environment">` 폴백 — 이 경우에도 가이드/체크리스트 UI는 촬영 전 화면에서 유지
- 상단: 환자명 + 의뢰 내용 (미분류 모드면 "미분류 촬영 / 촬영 후 의뢰서를 선택합니다"), 닫기 ✕
- 뷰파인더 오버레이(반투명, 촬영 이미지에는 미포함):
  - 상하 정렬 가이드라인 (티일 점선)
  - 안내 팁: "**쉐이드가이드를 절단연에 나란히**" / 전치부는 "**코 끝까지 나오게**"
- 컷 체크리스트: `① 쉐이드가이드 포함 → ② 정면`  ← 셋에서 둘로 (2026-08-23)
  - 현재 컷은 티일 외곽선, 완료 컷은 티일 채움. 순서는 **권장이지 강제 아님** — 셔터는 항상 동작
- 하단: 촬영 섬네일(좌) / 셔터(중) / "첨부 n" 버튼(우, 1장 이상일 때 표시)
- 셔터 시 플래시 효과. 촬영 수 제한 없음(체크리스트는 3컷까지만 표시)

### S4. 완료
- 체크 애니메이션 + "첨부 완료"
- 본문: "**{환자명} · {보철종류}** 의뢰서에 사진 {n}장이 원본 화질로 첨부됐어요. 덴플로우 치과기공소에 알림을 보냈습니다."
- 버튼: [오늘 의뢰로 돌아가기](메인) / [추가 촬영](서브)
- 홈 복귀 시 토스트: "{환자명} 촬영 완료 · 기공소 알림 전송됨"

### S5. 미분류 매칭
- 타이틀 "어느 의뢰서에 첨부할까요?" + "방금 찍은 사진 n장 · 최근 의뢰서 순"
- 안내 배너: "지금 건너뛰어도 사진은 **미분류함**에 안전하게 보관되고, 데스크에서 나중에 분류할 수 있어요."
- 리스트: `쉐이드 대기` 상태의 최근 의뢰서만 우선 노출
- 하단: "나중에 분류 (미분류함으로)"

### S6. 미분류함 (프로토타입에 없음 — 추가 구현)
- 홈에서 진입 가능한 서브 화면. 미분류 사진 묶음(촬영 세션 단위) 리스트
- 각 묶음 탭 → S5와 동일한 매칭 UI
- 데스크톱 웹에서도 동일 기능 제공

## 4. 데이터 모델

```typescript
// 치과 (테넌트)
interface Clinic {
  id: string;
  name: string;              // "미사바른치과"
  loginId: string;           // 치과 단위 공용 계정
  createdAt: Date;
}

// 스태프 (치과 내 개인 식별용 — 간단 PIN)
interface Staff {
  id: string;
  clinicId: string;
  name: string;
  pin: string;               // 4자리, 해시 저장
}

// 의뢰서
interface Case {
  id: string;
  clinicId: string;
  labId: string;             // MVP에서는 덴플로우 고정
  patientName: string;
  workType: WorkType;        // 아래 enum
  toothNumbers: string[];    // FDI 표기: ["26"], ["36","37"]
  shadeStatus: 'WAITING' | 'DONE';   // 쉐이드 사진 유무로 자동 전이
  status: 'OPEN' | 'IN_PROGRESS' | 'COMPLETED';
  memo?: string;
  createdAt: Date;           // 리스트 정렬 기준
}

type WorkType =
  | 'ZIRCONIA_CROWN' | 'PMMA_TEMP'
  | 'INLAY_HYBRID' | 'INLAY_ZIRCONIA'
  | 'CUSTOM_ABUTMENT' | 'CUSTOM_ABUTMENT_ZIR';

// 쉐이드 사진
interface ShadePhoto {
  id: string;
  caseId: string | null;     // null = 미분류
  clinicId: string;
  staffId?: string;
  sessionId: string;         // 같은 촬영 세션(미분류 묶음 매칭 단위)
  originalUrl: string;       // 원본 (재압축 금지)
  thumbnailUrl: string;      // 서버 생성 섬네일 (긴 변 480px)
  cutLabel?: 'SHADE_TAB' | 'FRONT' | 'FREE';  // 체크리스트 순서 기반 자동 라벨
  width: number; height: number; bytes: number;
  takenAt: Date;
}

// 알림
interface Notification {
  id: string;
  toLabId: string;
  type: 'SHADE_UPLOADED';
  caseId: string;
  photoCount: number;
  read: boolean;
  createdAt: Date;
}
```

상태 규칙:
- `ShadePhoto`가 Case에 1장 이상 귀속되면 `Case.shadeStatus = 'DONE'`
- 미분류 사진이 매칭되면 `caseId` 채우고 위 규칙 적용

## 5. API 스케치

```
POST   /api/auth/login              # 치과 공용 로그인 → 세션
POST   /api/auth/pin                # 스태프 PIN 선택 (세션에 staffId 부착)

GET    /api/cases?days=7&query=     # 홈 리스트 (초성 검색 서버 처리)
GET    /api/cases/:id               # 케이스 상세 (+ photos)
POST   /api/cases                   # 의뢰서 작성 (데스크톱, MVP 최소 폼)

POST   /api/photos/presign          # S3 presigned URL 발급 { caseId? , sessionId }
POST   /api/photos/commit           # 업로드 완료 통지 → 섬네일 생성 job, 알림 발송
POST   /api/photos/match            # { sessionId, caseId } 미분류 → 케이스 귀속
GET    /api/photos/unsorted         # 미분류함 (세션 단위 그룹)

GET    /api/lab/notifications       # 기공소 알림 목록 (폴링 or SSE)
```

업로드 구현 노트:
- 클라이언트 → presigned URL로 원본 직접 업로드 (서버 경유 금지, 대용량 대비)
- `commit` 시 EXIF 회전 보정만 허용, 화질 변경 금지
- 오프라인/전송 실패 대비: 업로드 큐 (IndexedDB) + 재시도. 실패 사진은 로컬 보관 후 재전송

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 같은 환자 의뢰서가 2건 (예: 상·하악 별건) | 리스트에 둘 다 노출, 작성시각으로 구분. 케이스 카드에 치식 표기가 구분자 역할 |
| 촬영 중 앱 이탈/전화 수신 | 촬영분은 세션에 로컬 보존, 복귀 시 카메라 화면 복원 |
| 업로드 중 네트워크 끊김 | 큐에 보관, 연결 복구 시 자동 재시도. 홈에 "전송 대기 n장" 배지 |
| 잘못된 케이스에 첨부함 | 케이스 상세에서 사진 길게 눌러 "다른 의뢰서로 이동" (미분류 매칭 UI 재사용) |
| 완료된 케이스에 추가 촬영 | 허용. `shadeStatus`는 DONE 유지 |
| PIN 없이 촬영 | 허용하되 `staffId` null. 스태프 식별은 편의 기능이지 장벽이 아님 |

## 7. 구현 순서 (권장)

1. **Phase 1 — 세로 슬라이스**: Clinic/Case/ShadePhoto 모델 + S1→S2→S3→S4 기본 플로우 + presigned 업로드 + 기공소 알림 목록. (미분류·검색·PWA 제외하고 끝까지 관통)
2. **Phase 2 — 안전망**: 미분류 플로우(S5·S6), 업로드 큐/재시도, 초성 검색
3. **Phase 3 — 도달성**: PWA(홈 화면 추가, 아이콘=brand 심볼), 웹푸시, (선택) 알림톡 딥링크
4. **Phase 4 — 품질**: 컷 라벨 자동화 고도화, 데스크톱 미분류 관리, 기공소 화면 개선

각 Phase 종료 시 프로토타입과 나란히 놓고 화면·문구 일치 여부를 확인할 것.

### 2026-08-23

- **'쉐이드탭' → '쉐이드가이드'.** 진료실에서 부르는 이름입니다.
- **컷 셋 → 둘** (③ 자유컷 뺌). 원본 화질로 담아서 한 장이 크고,
  케이스마다 세 장이면 저장소가 금세 찹니다. 색을 정하는 데 실제로
  쓰이는 것은 앞의 둘입니다. **권장 장수지 상한이 아닙니다** —
  셔터는 계속 눌립니다.
- **전치부는 코 끝까지.** 앞니는 색만 맞아서는 안 되고 얼굴 안에서
  맞아야 합니다(입술선·피부톤). 의뢰서 치식(FDI 견치~견치)으로
  저절로 켜지고, 손으로도 바꿉니다.
- **안내는 한 마디로.** 문장은 아무도 안 읽습니다 — 환자가 입을
  벌리고 있고 한 손엔 폰, 한 손엔 쉐이드가이드입니다.
- **폰으로 들어온 치과는 `/` 에서 `/m` 으로** 보냅니다. 태블릿은
  안 보냅니다(데스크가 아이패드로 의뢰서를 씁니다).

### 2026-08-21 (만들 때 정한 것)

- **쉐이드 사진만 원본**, 나머지는 하던 대로 줄입니다.
- **공용계정 + PIN 을 안 만들었습니다.** 지금 계정 그대로 씁니다 —
  인증을 하나 더 두면 기존 권한 규칙과 섞이는 자리가 생깁니다.
- **섬네일 파일을 안 만듭니다.** 저장소가 줄여서 내줍니다.
  원본은 손 하나 안 댑니다.
