# 자동 템포러리 — 스캔에서 치과 프린터 출력까지

사용자 목표 (2026-10-06):

> 덴플로우에 들어오는 스캔을 보철물 '자동 템포러리' 로 의뢰하면,
> 덴트버드(이마고웍스) 웹 자동디자인으로 올려 완성된 STL 을 받고,
> 오르카 슬라이서로 동일한 각도(x 135°)로 슬라이스하여 **치과 프린터로 원격출력**까지.

확정된 조건:

- 프린터는 **FDM · Bambu**, 그리고 **기공소가 아니라 치과에 있습니다**
- 덴트버드는 **과금만 하면 API 가 필요 없습니다** (치식·상하악·마진을 자동으로 잡아 줍니다)
- '자동 템포러리' 는 **아직 상품이 아닙니다.** 치과 눈에 띄면 안 됩니다

---

## 1. 한 건이 흘러가는 모습

| 때 | 어디서 | 무슨 일 |
|---|---|---|
| T+0 | 치과 | 스캔 → 내보내기. 에이전트가 올리고 주문서가 열림 |
| T+0 | 치과 | 치식 찍고 보철물 **자동 템포러리** → 주문완료 |
| T+5m | 기공소 | 덴트버드에 올리고 클릭 몇 번 → STL 내려받아 **지켜보는 폴더**에 떨어뜨림 |
| ~ | 기공소 PC | 방향 맞추기 → 오르카 CLI 슬라이스 → `.gcode.3mf` 를 덴플로우에 올림 |
| ~ | **치과 PC** | 에이전트가 출력 작업을 받아 내려받음 |
| ~ | **치과 랜** | 프린터에 FTPS 로 올리고 MQTT 로 출력 시작 |
| ~ | 치과·기공소 | 진행률이 주문 화면에 올라옴 → 출력완료 |

배송이 없습니다. 이게 치과에 프린터를 두는 이유 전부입니다.

## 2. 치과 프린터에 어떻게 닿는가 — **포트포워딩을 버립니다**

### 지금까지의 방식과 그 값

외부 IP + 포트포워딩으로 프린터에 직접 붙는 방식은 치과 한 곳일 때는 됩니다. 늘어나면 무너집니다.

- **프린터를 인터넷에 내놓는 것입니다.** Bambu 의 LAN 인증은 **8자리 액세스 코드** 하나뿐이고
  인증서는 자체 서명입니다. 시도 횟수 제한도 없습니다. 열어 두면 지나가는 스캐너가 찾아냅니다 —
  올리고, 출력을 걸고, 카메라를 봅니다
- **치과 공유기는 대개 통신사 장비**입니다. 치과마다 사람이 가서 설정해야 합니다
- **유동 IP** 면 어느 날 조용히 끊깁니다. DDNS 를 또 붙여야 합니다
- 치과에 "방화벽에 구멍을 뚫어 달라" 고 말해야 합니다

### 바꿀 방식 — 이미 치과에 깔려 있는 것을 씁니다

**덴플로우 에이전트에 '출력' 역할을 더합니다.** 치과 PC 는 이미 에이전트를 켜 두고 스캔을
올리고 있습니다. 같은 프로그램이 출력 작업도 받아 옵니다.

```
기공소 PC                    denflow.kr                    치과
  슬라이스                        │                     에이전트 (이미 있음)
  .gcode.3mf ──── 올림 ────────► │ ◄──── 물어봄 (HTTPS, 밖으로만) ───┤
                                 │ ───── 작업 + 서명 URL ───────────► │
                                 │                                    │ FTPS 990 ─► 프린터
                                 │ ◄──── 진행률 (MQTT 로 읽은 값) ────┤ MQTT 8883 ─►
```

**치과 쪽으로 들어오는 연결이 하나도 없습니다.**

| | 포트포워딩 | 에이전트 |
|---|---|---|
| 공유기 설정 | 치과마다 필요 | **없음** |
| 고정 IP / DDNS | 필요 | **없음** |
| 인터넷에 노출되는 것 | 프린터 | **없음** |
| 치과에 부탁할 것 | 방화벽 구멍 | 이미 켜 둔 프로그램 |
| 치과가 늘면 | 한 곳씩 방문 | 그대로 |

프린터의 **액세스 코드는 치과 PC 에만 둡니다.** 우리 DB 에 넣지 않습니다 — 남의 하드웨어
열쇠를 우리가 들고 있을 이유가 없습니다. 서버에는 **기종과 필라멘트만** 둡니다.
슬라이스 프로파일을 고르는 데만 씁니다.

> 스캐너 PC 와 프린터가 **같은 랜**에 있어야 합니다. 보통 한 치과 안이라 문제가 없습니다.
> 떨어져 있으면 그때만 프린터 옆 PC 에 에이전트를 하나 더 깝니다.

## 3. 슬라이스는 기공소에서 합니다

치과 PC 에 오르카를 깔지 않습니다.

- 프로파일이 치과마다 흘러가면 **"같은 설정으로 뽑았다" 가 그날부터 거짓**이 됩니다
- 치과 PC 는 **아무것도 결정하지 않는 전달자**여야 합니다. 받아서 넘기는 것뿐
- 에이전트 용량도 그대로 둘 수 있습니다

```bash
orca-slicer --slice 0 \
  --load-settings "<기계>.json;<공정>.json" \
  --load-filaments "<필라멘트>.json" \
  --export-3mf "ORD-261007-001.gcode.3mf" \
  "ORD-261007-001_crown_놓임.stl"
```

★★ **회전 옵션을 쓰지 않습니다.** 오르카 2.4.2 에서 깨져 있습니다 — 실측:

| | |
|---|---|
| `--rotate 30` (Z) | 됩니다 |
| `--rotate-x 150` | exit 127 |
| `--rotate-x 10` | **세그폴트** |

그래서 메쉬를 **우리가 돌려서**(`orient.py`) 넘깁니다. 오르카는 자르기만 합니다.
쓴 각도를 주문에 적어 둘 수 있고, 돌린 모습을 그림으로 뽑을 수 있습니다.

★ 경로는 **절대 경로**여야 합니다(상대면 "can not find setting file").
  `--load-settings` 는 **기계 먼저, 공정 나중**. 프로파일은 펼치지 말고 오르카가
  들고 있는 파일을 그대로 가리키되, **셋이 서로 맞아야** 합니다(compatible_printers).

### Bambu 로 보내는 사슬

```
.gcode.3mf  →  FTPS(990, 액세스 코드)로 SD 에 올림  →  MQTT(8883)로 출력 시작
```

- **MQTT 로 출력을 시작할 수 있는 건 `.3mf` 뿐입니다. 생 `.gcode` 는 안 받습니다.**
  오르카의 `--export-3mf` 결과가 정확히 그 형식이라 변환이 없습니다
- 프린터는 **LAN 모드**로 켜 둡니다. 필요한 값은 **IP · 액세스 코드 · 시리얼** 셋
- 파이썬은 `bambu-connect` 또는 `bambu-mqtt-comms`. 클라우드로 붙는 길은 비공식이라 쓰지 않습니다

## 4. 사람이 없는 곳에서 불이 나지 않게

**치과에는 기공사가 없습니다.** 이게 기공소에 두는 것과 가장 다른 점입니다.

- **베드가 비었는지는 기계가 모릅니다.** 전 출력물이 그대로 있으면 그 위에 뽑습니다.
  → 출력 시작 전에 **치과가 "베드 비움" 을 한 번 누릅니다.** 누르기 전까지 작업은 대기합니다
- 프린터가 **idle 이 아니면** 보내지 않고 줄을 세웁니다
- 필라멘트 소진·문 열림·노즐 막힘 같은 프린터 오류를 **그대로 주문 화면에 띄웁니다**
- 첫 레이어가 올라간 뒤 **카메라 정지 영상 한 장**을 주문에 붙입니다 (나중 단계)
- 자동 재시도는 **올리기·내려받기만**. 방향·슬라이스·출력은 한 번 실패하면 사람을 부릅니다

사용자 원칙 그대로 — *"1개라도 주문이 잘못 들어온다면 치명적"*. 조용히 실패하는 자동화를 만들지 않습니다.

## 5. '자동 템포러리' 를 어떻게 감추는가

**홈페이지와 수가표는 손댈 것이 없습니다.** 확인했습니다 —
`LandingPage.tsx` 의 `PRODUCTS` 와 `price-sheet/index.ts` 의 `DEFAULT_PRICE_SHEET` 는
**손으로 쓴 목록**이고 제품표를 읽지 않습니다. 제품을 추가해도 공개 화면에는 나타나지 않습니다.

남는 곳은 **치과 주문등록의 보철물 목록** 하나입니다.

`is_active` 를 끄면 모든 치과에서 사라지지만 **시험도 못 합니다.** 그래서 성질을 하나 더 둡니다 —
`prosthesis/index.ts` 가 이미 말하는 원칙대로, *"종류가 자기 성질을 들고 있어야 합니다."*

```ts
/** 아직 상품이 아니다. 치과 목록에서 감추고 센터 화면에서만 고른다 */
isInternal: boolean;
/** 주문이 들어오면 사람 손 없이 디자인·슬라이스·출력까지 간다 */
autoPipeline: boolean;
```

- 치과 주문등록 → **안 보임**
- 디자인센터 주문등록 → **보임** (배지 '내부'). 치과를 골라 등록하면 실전 시험이 됩니다
- 상품화할 때 성질 하나만 끄면 끝. 코드를 안 고칩니다

## 6. 단계로 쪼갠다

### 0단계 — 그릇
- `isInternal` · `autoPipeline` 성질, 제품 '자동 템포러리' 한 줄
- `auto_jobs` 표 (주문 · 단계 · 시도 · 실패사유)
- 주문상세 **진행 줄**: 디자인 → 슬라이스 → 치과 전송 → 베드 확인 → 출력중 → 완료
- 치과 프린터 등록 화면 (기종·필라멘트는 서버, 액세스 코드는 치과 PC)

### 1단계 — 폴더에서 치과 프린터까지 (덴트버드 API 없이 끝까지 자동)
덴트버드에서 **사람이** 내려받은 STL 을 파일 이름에 ORD 번호를 넣어 폴더에 떨어뜨립니다.
그 순간부터 방향 맞추기 → 슬라이스 → 치과 에이전트 → 출력 → 진행률 회신까지 무인입니다.

### 2단계 — 방향 맞추기 확정
서로 다른 케이스 2건의 STL 로 좌표계가 일정한지 재 봅니다 (7절).

### 3단계 — 덴트버드 API 로 교체 (건수가 늘면)
사람이 올리고 내리던 자리에만 API 를 꽂습니다. 뒷부분은 그대로 씁니다.

## 7. 각도 — 정해졌습니다 (2026-10-07)

**x 135° / y 0°.** 실제 크라운(차정순 27번)을 여섯 자세로 놓고 재서 골랐습니다.

| 각도 | 높이 | 처진 면적 | **내면 처짐** |
|---|---|---|---|
| 그대로 | 8.3mm | 46.3 | 37.5 |
| 뒤집기 | 8.3mm | 80.7 | 0 |
| x150 y140 | 13.6mm | 51.6 | **35.9** |
| **x135** | 12.2mm | **48.9** | **0** |
| x45 | 10.6mm | 99.0 | 62.0 |

**「내면 처짐」이 고른 까닭입니다** — 크라운 **안쪽**에 서포트가 붙는 면적입니다.
거기 붙으면 떼기 어렵고 맞춤에 그대로 영향이 갑니다. x135 는 내면이 0 이면서
전체 처짐도 가장 적습니다.

★ 값은 `orient.py` **한 곳**에만 둡니다. 창·명령줄·안내문에 따로 적으면
  어느 날 서로 달라지고, 그러면 "같은 각도로 뽑았다" 가 거짓이 됩니다.
  보내기 창에서 그때그때 바꿀 수는 있습니다.

## 7-1. 좌표계 걱정은 없는 문제였습니다

각도는 **자동 디자인이 끝난 크라운을 슬라이서에서 돌릴 때** 쓰는 값입니다.

사람이 눈으로 돌리면 문제가 없습니다. 고정값을 박으려면 **들어오는 STL 의 좌표계가 케이스마다
같아야** 합니다. 다르면 처음 몇 건은 맞는 듯하다가 어느 날 서포트가 교합면에 붙습니다.

**덴트버드가 상·하악과 치식을 자동 판별한다는 점이 좋은 신호입니다.** 판별하려면 해부학적으로
정렬해야 하고, 그 자세로 내보낼 가능성이 높습니다. 그러면 고정 각도가 그대로 통합니다.

**재 보면 압니다.** 과금 뒤 서로 다른 케이스 2건(되면 상악 1 · 하악 1)을 STL 로 내보내 주세요.

- 자세가 같으면 → 고정 각도 그대로
- 다르면 → 내면 법선 평균으로 **삽입축**을 구해 정규 자세로 돌린 뒤 그 기준에서 각도

어느 쪽이든 **돌린 결과를 그림으로 남겨 주문에 붙입니다.** 출력이 끝난 뒤에 알면 늦습니다.

## 8. 덴트버드 — 과금하면 API 가 필요 없습니다 (2026-10-06 확인)

유료 계정이면 웹에서 **STL · OBJ · PLY** 를 그대로 내려받습니다. 과금은 내보낸 설계 단위로
대략 **STL 당 4~5 USD**, 또는 월 50건 Lite 플랜과 무제한 플랜이 따로 있습니다. 견적은 받아야 합니다.

API 는 기능을 열어주는 것이 아니라 **케이스당 사람 손 3번(올리기·클릭·내려받기)을 없애는 것**뿐입니다.
건수가 적으면 과금만으로 충분합니다. 케이스당 비용은 '자동 템포러리' 단가에 반영해야 합니다.

**덴트버드가 잡은 치식을 믿지 말고 대조합니다.** 자동 판별이 틀렸을 때 아무도 모르는 게 위험합니다.
클릭하는 화면에 치식이 떠 있으니 **주문서 치식과 다르면 멈추는 것**을 절차로 둡니다.
