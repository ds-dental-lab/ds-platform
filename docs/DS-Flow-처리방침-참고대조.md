# 참고 문서 대조 — 큐브세븐틴(NeXways) 처리방침·약관

> 유사 업체의 개인정보처리방침·이용약관을 받아 **우리 실제 동작과 대조**한 것입니다.
> 무엇을 참고하고 무엇을 **절대 베끼면 안 되는지**를 가립니다.
>
> 작성 2026-08-12 · 우리 쪽 사실은 [DS-Flow-개인정보-처리현황](DS-Flow-개인정보-처리현황.md) 기준

---

## 1. 가장 큰 수확 — 그 회사는 스스로를 '처리자' 로 놓았습니다

우리가 못 정하고 있던 질문(수탁자냐 처리자냐)에 대한 **실무 선례**입니다.

그 회사는 **자기가 개인정보처리자**이고, **기공소·밀링센터를 수탁자**로 적었습니다
(제7조에 수탁자 상호와 위탁업무를 표로 공개). 구조가 우리와 거의 같습니다.

```
환자 → 치과(회원) → 플랫폼(개인정보처리자) → 기공소(수탁자)
                     └ Den Flow 의 디자인센터 자리
```

**이 선례를 따른다면 우리가 할 일**

1. Den Flow(디자인센터)가 **자체 처리방침**을 공개
2. **기공소를 수탁자로 명시** — 상호·위탁업무·보유기간을 표로
3. 기공소와 **위탁계약서** 체결 (법 제26조 필수 조항: 목적 외 처리금지,
   기술적·관리적 보호조치, 재위탁 제한, 관리·감독, 손해배상)
4. 치과로부터는 환자 정보를 받는 근거를 정리

> 다만 이건 **그 회사의 법적 판단**이지 정답이 아닙니다. 우리 계약 형태가
> 다르면 결론도 달라집니다. 자문 때 "유사 업체는 이렇게 하고 있다" 는
> 자료로 쓰시면 논의가 훨씬 빨라집니다.

## 2. 그대로 가져다 쓸 수 있는 것

| 항목 | 왜 |
|---|---|
| **전체 목차 구성** (총칙 → 수집·이용·보유 → 권리 → 파기 → 안전성 → 위탁 → 열람청구 → 구제 → 고지) | 표준 양식 그대로입니다. 빠진 조가 없습니다 |
| **법정 보존기간 목록** | 아래 3항 참고 — 사실이라 그대로 씁니다 |
| **권익침해 구제방법** (분쟁조정위 1833-6972, 침해신고센터 118 …) | 기관 연락처는 사실 |
| **정보주체 권리 행사 방법** (서면·전자우편·FAX, 위임장 서식) | 법령·고시 인용 |
| **처리 항목을 필수/선택으로 나눈 표 형식** | 우리 항목으로 채우면 됩니다 |

### 우리에게 그대로 해당되는 법정 보존기간

- **치과기공물제작의뢰서 2년** (의료기사 등에 관한 법률) ← 제가 말씀드린 것과 일치
- 계약·대금결제·재화공급 기록 **5년**, 소비자 불만·분쟁처리 **3년**,
  표시·광고 **6개월** (전자상거래법)
- 인터넷 로그·접속지 추적자료 **3개월** (통신비밀보호법)

> **주의** — 이건 그 회사 기준입니다. 우리가 전자상거래법 적용 대상인지
> (사업자 간 거래라 소비자보호법 적용이 다를 수 있음) 확인이 필요합니다.

## 3. ★ 절대 베끼면 안 되는 것 — 우리는 안 하는 일입니다

여기가 제일 중요합니다. 아래를 그대로 옮기면 **하지도 않는 일을 한다고
공표**하는 것이고, 그건 양식 문제가 아니라 거짓 고지입니다.

| 그 회사 문구 | 우리 실제 |
|---|---|
| **AI 연구개발 목적으로 구강스캔·질환정보 처리** (제2조 1.3) | **안 합니다.** 학습도, 통계 활용도 없습니다 |
| **은행계좌정보, 신용카드번호** 수집 | **없습니다.** 결제 정보가 시스템에 아예 없습니다 |
| **의사면허번호** 수집 | **안 받습니다** |
| **성별** 수집 | 그런 칸이 **없습니다** |
| 생년월일 **필수** | 우리는 **선택**입니다 (`patients.birth_date`) |
| 「전자상거래법」에 따른 소비자 보호 조항 | 우리는 **사업자 간(B2B)** 거래입니다 |
| 정기(분기 1회) 자체 감사, 물리적 출입통제 구역, 문서 잠금장치 | **아직 안 합니다.** 쓰려면 먼저 하셔야 합니다 |
| 개인정보 보호책임자 이름·연락처 | 우리 사람으로 바꿔야 합니다 |

**AI 항목이 특히 위험합니다.** 그 회사는 그걸 하려고 **별도 동의**를 받는
구조를 짰습니다. 우리가 안 하면서 문구만 옮기면, 받지도 않은 동의를
받은 것처럼 쓰게 됩니다.

## 4. 반면교사 — 이 문서 자체가 '베끼기의 위험' 을 보여 줍니다

받으신 **이용약관**에는 눈에 띄는 결함이 있습니다.

- **제3조 제목은 「이용약관의 효력 및 변경」인데 내용은 개인정보 열람·정정·
  삭제 권리**입니다. 처리방침 제3조가 통째로 잘못 들어갔습니다
- **제9~14조가 문자메시지 발송 서비스 조항**입니다 — 발신번호 변작 방지,
  스팸 전송제한, 전기통신역무 중지. 보철 플랫폼과 무관합니다
- **제25조에 '충전 잔여금액의 20%' 환급** 조항 — 선불 충전 서비스의 흔적
- 「회사의 의무」가 **제9조와 제16조에 두 번** 나옵니다

즉 **다른 서비스 약관을 가져와 다 지우지 못한 문서**입니다.
우리가 이걸 또 베끼면 결함까지 물려받습니다.

**이용약관은 참고 가치가 낮습니다.** 처리방침만 참고하시고, 약관은
우리 서비스(B2B 보철 주문·정산)에 맞춰 새로 쓰는 편이 낫습니다.

## 5. 우리 처리방침에 들어갈 내용 (뼈대)

그 회사 구조 + 우리 실제 사실로 채운 것입니다. **문구가 아니라 목차와
채울 값**입니다.

| 조 | 우리가 채울 값 |
|---|---|
| 처리 목적 | ① 회원 가입·관리 ② 보철 제작주문 접수·중계 ③ 청구서 발송·정산 (**AI 없음**) |
| 처리 항목 | 환자: 이름·차트번호·생년월일(선택)·치식·보철정보·스캔파일<br>회원: 이름·이메일·휴대전화<br>사업자: 상호·사업자번호·대표자명·연락처 |
| 보유기간 | 회원 탈퇴 시까지 / 치과기공물제작의뢰서 **2년** /<br>파일 **완료 후 14개월** / 접속기록 **2년** / 지운 것 **30일** |
| 파기 | **자동 배치 아님.** 관리자가 건수를 확인하고 실행. 저장소 파일까지 삭제 |
| 안전성 확보조치 | RLS 기반 접근통제 · 비밀번호 해시 · **비공개 저장소 + 단기 서명 URL** ·<br>접속기록 2년 · 권한 최소화(사용자는 금액 못 봄) |
| 위탁 | 기공소(보철 제작) · Supabase(클라우드 인프라, **서울 리전**) |
| 보호책임자 | **정하셔야 합니다** — 이름·부서·연락처 |
